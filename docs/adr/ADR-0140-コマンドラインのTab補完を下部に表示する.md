# ADR-0140-コマンドラインのTab補完を下部に表示する

- 状態: 採用
- 日付: 2026-10-17
- 関連 Issue: #55 / #102
- 置換元: なし（ADR-0131 の入力表示を補完に拡張）

## 背景

Ex・検索・置換の入力中に Tab を押しても候補が見えず、何が補完されるか分からない。実 Neovim は wildmenu を自前のグリッドに描画するため、グリッドを表示しない本文では候補が不可視になる。

## 検討した選択肢

1. 独自に候補を取得して表示する。実 Neovim と二重管理になり、補完結果の食い違いが出るため不採用。
2. `ext_popupmenu` を有効化し、実 Neovim の `popupmenu_show/select/hide` を下部のコマンドライン表示の直上に描画する。候補の計算は実 Neovim が所有し、GUI は表示だけを受け持つ。採用。
3. `wildoptions` に `pum` を強制追加する。利用者の設定を上書きするため不採用。既定（`pum` 含み）のままにし、外したら補完表示も出ないことを仕様とする。

## 決定と理由

- UI 接続に `ext_popupmenu` を追加し、`VimCompletion`（候補・選択位置）を `ModeUpdate` 経由で渡す。TypeScript 契約は生成器で更新する。
- 候補一覧はコマンドライン表示の直上に置き、選択行を強調する。キー操作は従来通り実 Neovim が受け持つ（Tab/矢印/Esc）。
- `:Marxen` の引数補完カスタマイズは対象外。コマンド名自体の補完は実 Neovim の既定で効く。

## 結果・制約

- Tab 補完はコマンドライン（`:`/`/`）全般で表示される。挿入モード補完は今回の表示対象に含めない。
- ブラウザ表示（読み取り専用・Neovim 未接続）では補完は出ない。実デスクトップでの目視は未実施。

## 確認方法

- `cargo test` の `vim_ui` 単体（合成イベント）と `vim_input` の `:color <Tab>` 実機（候補非空・Esc で消去）。
- `npm run contracts:check` と関連 Vitest（shell・registry-client）。
- 実デスクトップでの Tab 表示の目視は未実施として区別する。
