# 相対画像の遅延水和を共通化する

- 状態: 採用
- 日付: 2026-10-08
- 関連 Issue: #6（描画 0060-0069 予約の 0063）

## 背景・選択肢

相対画像の参照を描画時に絶対化する方法と、表示用の取得だけ後付けにする方法がある。取得器の形を閲覧と部品で別々にする方法と、共通の呼び出しにまとめる方法がある。

## 決定と理由

- 描画器は相対参照を Markdown のまま残し、絶対の生経路や `file://` を HTML に書かない。表示用の取得は `src/domain/image-sources.ts` の共通呼び出し `(src, signal) => Promise<string | null>` を使い、`src/presentation/images/hydrate-images.ts` が消毒済み HTML の配置後に呼ぶ。利用者側は文書単位の Rust 読込器を裏に置く。
- 非 ASCII 参照は `%` 復号して著者の経路に戻してから渡す。戻り値は bytes 系と自前系（`https:`、`blob:`、`data:image/`、`asset:`、`tauri:`）だけ受け、実行系は捨てる。空応答と失敗は原文表示のままとする。
- 中断・破棄・文書切替の遅着は書込まない。配置済みの印で二重取得を止め、参照が変っていたら他文書向けの応答を捨てる。貼付画像も相対参照になるので同じ経路で表示する。

## 結果・制約・確認方法

- Vitest（`images.test.ts`）で相対判定・復号・許可系・中断と破棄と切替を検証し、Playwright（開発専用 harness の仮取得器）で部品内の置換と遅着破棄を検証する。
- 未実施として残す。実機の Rust 読込器との結合と各 OS 実 WebView での表示確認。
