# ADR-0139-アプリ操作のショートカットをvimrc定義にする

- 状態: 採用
- 日付: 2026-10-17
- 関連 Issue: #55 / #102
- 置換元: なし（ADR-0131 のマッピング優先を具体化）

## 背景

アプリ既定のショートカット（保存・クイックオープン・パレット・設定・インライン・AI）が Rust 側の隠し登録で有効になり、エディタ外では Vim を迂回して発火する。Vim 利用者からは干渉の指摘があり、保存は `:w`、操作は vimrc の `noremap` で定義したいとの要望がある。

## 検討した選択肢

1. 現状維持でヘルプに説明だけ足す。干渉自体は残るため不採用。
2. 既定登録をやめ、管理ブロックへ既定の `noremap` 行を埋め込む。既存ファイルへの無断追記と Rust/TS 両面の形式変更が必要で移行が重いため今回は見送り。
3. vimrc のマッピング優先は維持し、`g:marxen_default_shortcuts = 0` で既定登録を全部止められるようにする。既存動作は既定で変わらず、vimrc だけで定義し直せる。採用。

## 決定と理由

- エディタ内は従来通り利用者のマッピングが最優先（`mapcheck`）。
- `let g:marxen_default_shortcuts = 0` を vimrc に書くとアプリ既定の6種を登録しない。以降は `:Marxen <操作名>` を `noremap` で定義する。
- `:w` は従来通り Rust の保存経路に統一されており、保存の既定操作は Vim そのものとする。
- キーボードショートカットのヘルプに vimrc 定義例（6種の `nnoremap` と無効化変数）を常設する。

## 結果・制約

- 既定動作は変わらない（変数未設定＝従来通り登録）。
- エディタ外フォーカス時のアプリ直発火は残る。エディタ外では Neovim が関与しないためで、仕様としてヘルプと README に記載する。
- GUI 設定（テーマ・文字サイズ等）の vimrc 変数化は対象外。操作の定義のみ vimrc 化する。

## 確認方法

- `cargo test --manifest-path src-tauri/Cargo.toml --locked --features dev-tools vim_input` で、無効化時の既定不発火と `:Marxen` 直呼びの有効を確認する。
- ヘルプダイアログに vimrc 定義例が表示されること（Vitest の shell 系テストが壊れないこと）。
- `npm run localization:check` で新規キーの不足がないこと。
