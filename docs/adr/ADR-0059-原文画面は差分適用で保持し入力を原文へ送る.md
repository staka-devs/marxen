# 原文画面は差分適用で保持し入力を原文へ送る

- 状態: 採用
- 日付: 2026-10-08
- 関連 Issue: #5（編集は #3 の grid、基盤は #4 の fetch_grid）

## 背景・選択肢

画面依存の plugin 面を毎回作り直す方法と、再描画差分を保持する方法を比較した。原文画面の入力を browser 挿入として扱う方法と、実 Neovim への原文入力として送る方法を比較した。

## 決定と理由

- 原文画面は `NvimGridState` に `applyGridUpdates` で差分適用し、触れていない行・桁を捨てず、広い字幅・強調・反転・待機・ cursor を保つ。文書切替と表示閉鎖で初期化し、他緩衝の行を残さない。取得失敗は通知に留め、偽の画面を作らない。
- 原文画面の鍵入力は `serializeVimKey` で直列化して実 Neovim へ送り、確定文は `<` 退避して送る。未確定・ Process・ keyCode 229 は送らない。表示は読取専用の fallback を残し、端末のふりをしない。
- 殻は grid の再描画・強調・入力の保持だけを受け持ち、文書本文の改訂演算には触れない。

## 結果・制約・確認方法

- Vitest で広い字・ cursor 移動・原文鍵転送・確定一回・ browser 挿入抑止を検証する。Playwright では原文ビューの表示と読取専用の不変を製品ビルド（1425 番）で検証する。Rust は grid 再描画と実 Neovim の統合で検証する。
- 未検証として残す。各 OS の実 WebView における画面依存 plugin の表示・入力の確認。実機の結果を browser の成功から推定しない。
