# 名前付きAPI接続先の表示を安定IDで個別に管理する

- 状態: 採用
- 日付: 2026-10-15
- 関連: Issue #89（関連: #68、#79、#86）

## 背景

名前付きAPI接続のチャット候補は安定した接続IDを値に使うが、AI表示設定は固定の接続種別だけを保持していた。候補の絞り込みが接続IDを種別一覧と比較するため、登録した接続先を個別に隠せなかった。同名や同形式の接続を区別できず、選択中の候補を隠す手段もなかった。

## 検討した選択肢

接続種別の非表示を接続IDにも流用する方法、接続名で照合する方法、安定IDごとの非表示一覧を別に持つ方法を検討した。前二者は双子接続の混同と旧設定の破壊を招くため、安定IDによる分離を採用する。

## 決定と理由

`AiViewPreferences` に任意の `hiddenConnectionIds` を持たせ、照合は安定IDの一致だけで行う。種別単位の `hiddenProviders` と接続単位の指定は互いに波及させず、モデル単位の `HiddenAiModel` の接続スコープも従来どおり分離する。設定画面は登録済み接続を名前・通信形式・モデル・ endpoint で列挙し、既存の検索・キーボード操作と共存させる。登録がない場合は従来の単一の直接API種別を表示する。

選択中の候補を隠しても実際の選択・資格情報・会話は維持し、表示管理への入口と非表示の説明を示す。削除した接続の非表示指定は残しても混同しない。新規登録は常に新しい安定IDを発行するため、同名の再登録と取り違えない。旧設定は欠落値を空一覧として読み替え、ACP表示と再起動後の復元を維持する。

## 結果と制約

同じ通信形式や同じ名前の接続先がID単位で独立して表示・非表示できる。Rust・認証・課金通信の変更は不要で、表示設定は接続状態・文書・ネイティブ選択に影響しない。各OSの実WebView・IME確認は対象外とする。

## 確認方法

種別・接続・モデルの分離、旧設定の読み替え、双子接続の独立、選択中非表示の保持、再起動後の復元を対象テストで確認する。型・依存・地域化検査を通し、広狭UIの描画は分離した固定具で確認する。
