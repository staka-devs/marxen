# エージェントの利用状況を報告値のみで表示する

- 状態: 採用
- 日付: 2026-10-11
- 関連: GitHub Issue #59

## 状況

ACP は `session/update` の `usage_update`（`used`/`size`/`cost`）と、不安定な `session/prompt` 応答の `usage`（`inputTokens`/`outputTokens`/`totalTokens`/`thoughtTokens`/`cachedReadTokens`/`cachedWriteTokens`）で利用状況を報告する。後者の turn と session の範囲は実装で異なり（公式 ACP issue #1860）、汎用 ACP に口座 quota・reset 時刻・Copilot クレジットの標準欄はない。

## 決定

- `used`/`size` は現在の文脈占有、`cost` は累積セッション費用として報告通りに保持する。計画 quota とは解釈しない。
- `PromptResponse.usage` は対象範囲がエージェントごとに異なるため、範囲未定義として保持して合算しない。コンテキスト情報・セッション費用と、応答のトークン情報を別の報告として保持し、run・session 間の情報を混ぜない。
- token から quota・reset・消費額・金額を導出しない。未報告は欠落のままにし、零や仮の百分率を置かない。`_meta` の任意名や非公開 CLI 状態は読まない。
- 金額は十進文字列で保持し（`Eq` 契約維持）、負・非有限・JS 安全整数外の計数は報告ごと棄却する。
- run・session・報告元ごとの最新値を最大 32 件メモリ保持し、読取専用 snapshot IPC で再表示する。`usage` は非終端 event とし、`done`/`error`/`cancelled` の一度だけの終端を変えない。
- JSON の計数と受信時刻は安全な整数の数値として渡し、TypeScript も `number` として扱う。未報告の欄は省略し、金額の十進文字列と区別する。

## 検証

- 通知/応答の実 JSON 解析、無関係 session 拒否、不正値棄却、source/scope/reset/置換、終端・取消の単一性を Rust 検証で確認する。実 WebView/IME の確認と区別する。
