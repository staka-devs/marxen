# 文書操作をルート所有権と世代と位置で検証する

- 状態: 採用
- 日付: 2026-10-15
- 関連: #57、#83、[単一ルートの操作](ADR-0123-上部メニューと単一ルートの文脈操作を共有コマンドに集約する.md)

## 背景

相対パスと文書 revision だけでは、同名ファイルを持つ複数のフォルダー、フォルダーの開き直し、内容を変えない名前変更を区別できない。遅れて届いた保存・検索置換・画像・AI の操作を、その時点で画面に表示しているフォルダーへ転送してはならない。

## 選択肢

1. 現在のフォルダーと相対パスを都度参照する。実装は小さいが遅延操作の所有者を保証できない。
2. 文書ごとにフォルダーを複製して管理する。既存 Workspace、Neovim、保存経路の責務が重複する。
3. 既存 Workspace を所有する小さい application registry を置き、Rust が発行した所有権を既存の port と IPC に渡す。

## 決定と理由

3 を採用する。`RootRegistry` は既存 Workspace を所有し、正規化したルートから Rust が発行する安定 `rootId`、登録ごとに変わる `generation`、文書の相対パスと名前変更ごとに増える `position` を検証する。元の名前に戻した場合も、以前の位置情報を拒否する。ルートの追加 UI はこの変更で有効にせず、現在の単一フォルダー切替と未保存拒否を維持する。

文書 ID は Rust がルートを含む名前空間で発行し、閉じた文書の ID を再利用しない。ルートを扱う IPC は登録世代を、文書 IPC は捕捉した位置を必須にする。standalone actor と復旧 v1 の読み込みでは所有情報の欠落を許すが、デスクトップ文書操作では許さない。Rust 契約から TypeScript を生成する。

検索結果とイベントは生成元の所有権を保持する。TypeScript の直列操作は revision を更新しても、操作開始時の位置を保持する。ルートの開き直しや名前変更で失効した操作は自動転送・自動再適用しない。

AI のコピーは一つのルートの世代と各文書の位置を記録し、別ルートとの混在、名前変更後の差分適用、開き直し後の取り込みを拒否する。会話は最初に捕捉したルートを保持し、別ルートへ移る場合は新しい会話を開始する。実行中のコピーの pin と承認後の保存経路は従来のまま維持する。

復旧 v2 は安定 rootId と文書位置を保存する。v1 は元のルートと安全な相対パスを検証し、古い ID をルートごとの ID に移して Neovim の未保存状態を復元する。v2 のチェックポイント成功後に v1 を除去し、衝突や検証失敗では元の bytes を保持する。再起動後の復旧には現在の登録世代を付け、以前の操作を復活させない。

## 結果・制約

同名の相対パスを別ルートに登録でき、文書・画像・検索・復旧・AI の所有者を個別に検証できる。ルート ID は正規化したローカルパスを基にするため、フォルダー移動や別 OS への移送に同じ ID を保証しない。AI のコピーは OS の権限を隔離する sandbox ではない。

## 確認方法

application registry と実 Neovim を使い、二ルートの同名文書、保存先と Undo、誤所有者・古い世代・名前変更往復の拒否、画像の解決、未保存復旧 v1/v2、衝突時の元ファイル保持、AI の単一ルートと会話の継続を確認する。TypeScript では遅延要求とイベントの所有情報を検証する。各 OS の実 WebView / IME は #9 の検証として区別する。
