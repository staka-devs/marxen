# テキストと画像とフォルダーの名前変更を捕捉文脈で検証する

- 状態: 採用
- 日付: 2026-10-15
- 関連: #57、#85、[文書操作をルート所有権と世代と位置で検証する](ADR-0126-文書操作をルート所有権と世代と位置で検証する.md)

## 背景

エクスプローラーの名前変更は Markdown の文書 actor 経路に限定され、対応 UTF-8 テキスト・画像・フォルダーはツリーから名前を変更できない。複数ルート UI の有効化とは分け、単一ルートの所有権（安定 rootId と世代、文書の位置）を前提に、捕捉した対象だけを操作する必要がある。

## 選択肢

1. 全種別を文書 actor 経由に統一する。画像・フォルダーに不要な Neovim を起動し、未保存復旧と Undo の責務が崩れる。
2. OS コマンドへ直接委譲する。port と adapter を迂回し、上書き・リンク逸脱・世代検証を保証できない。
3. テキストは既存 actor の名前変更を再利用し、画像・フォルダーは使用中の storage port とネイティブ adapter で検証する。ツリーの捕捉文脈とダイアログを共通化する。

## 決定と理由

3 を採用する。対応 UTF-8 テキストは既存 actor の `rename` を再利用し、DocumentId・revision・未保存内容・Undo を維持する。画像はテキスト actor を作らず、捕捉した相対パス・種類・fingerprint で上書きなしのネイティブ名前変更を行い、タブとキャッシュを更新する。フォルダーは `DirectoryStorage::rename_dir` の port 経由で上書き・リンク逸脱・自分への移動を防ぎ、初期範囲では開いた子孫文書や AI 作業コピーがあるフォルダーを理由付きで拒否し、未保存文書を閉じない。ルート自身・衝突・古い世代・位置・disk 状態は既存の所有権検証で拒否し、結果の path mapping をツリー・画像タブ・フォーカスへ反映する。共通メニュー・F2・文脈メニュー・ダイアログを使い、自動リンク書換えや開いた子孫の透過移動は含めない。

## 結果・制約

ツリー対象のテキスト・画像・フォルダーを同一ダイアログから名前変更できる。フォルダー名変更で開いた子孫文書や AI 作業コピーがある場合は操作せず、理由を表示する。Markdown 内の画像・リンク参照の自動書換えは行わず、参照切れは表示上の未解決として残る。

画像データの fingerprint は読み取った同一バイト列から Rust が生成し、名前変更時の必須入力とする。GUI のハッシュ機能の有無による検証の省略は認めない。フォルダーの移動は Windows の `MoveFileExW`（置換フラグなし）、Linux の `renameat2(RENAME_NOREPLACE)`、macOS の `renamex_np(RENAME_EXCL)` で宛先作成との競合も上書きせず拒否する。対応する OS 機能が使えない場合は移動を拒否し、事前確認と通常の rename への代替は行わない。画像 URL キャッシュの失効は注入されたローダーまで伝え、失効前の応答による再登録も拒否する。

## 確認方法

実一時ファイルで名前変更と衝突・変更済み fingerprint・リンク逸脱・取消、テキスト actor の保存先と Undo 維持、画像と子フォルダーの参照更新を確認する。TypeScript では捕捉文脈の失効、ダイアログの翻訳とフォーカス復帰、タブとキャッシュの更新を確認する。実 OS ファイル操作と WebView は #9 で区別して確認する。
