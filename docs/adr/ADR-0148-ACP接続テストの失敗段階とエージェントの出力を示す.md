# ADR-0148-ACP接続テストの失敗段階とエージェントの出力を示す

- 状態: 採用
- 日付: 2026-10-21
- 関連 Issue: #111
- 置換元: なし

## 背景

ACP の接続テストが「ハンドシェイクに失敗しました: …」となり、どこで失敗したか分からない。エージェントが標準エラーに出すログイン要求などの原因文も、読取りスレッドの完了を待たずに組み立てていたため欠けることがあった。

## 決定と理由

- 握手の到達段階（`起動` / `initialize` / `session/new`）を失敗文に含める（例: 「ハンドシェイクに失敗しました（initialize）: …」）。
- 失敗時は子プロセスの回収後に標準エラーの読取り完了を最大 500ms 待ってから原因文に付ける。孫プロセスが標準エラーを保持していても待ち続けない。
- 再現用 mock に `--stderr-exit <文>`（標準エラーへ出力して終了）を追加する。

## 結果・制約

- npm 版 codex-acp・インストーラー版 opencode の失敗原因そのものは、この表示で利用者の環境から特定する。実機での接続成功は未確認。

## 確認方法

- `cargo test --test ai handshake_failure_reports_phase_and_agent_stderr`（Linux コンテナ（wslc）で実施）。
- 実機の codex-acp / opencode での接続テストは未実施。
