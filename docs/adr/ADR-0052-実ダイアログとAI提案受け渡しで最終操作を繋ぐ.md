# 実ダイアログとAI提案受け渡しで最終操作を繋ぐ

- 状態: 採用
- 日付: 2026-10-08
- 関連 Issue: #5（基盤は #4 の文書レジストリ、AI 契約は #7、描画は #6）

## 背景・選択肢

フォルダー選択と設定ファイル選択を手入力だけに頼る方法と、OS 標準ダイアログを使う方法を比較した。AI 支援の接続先・資格情報・送信範囲・提案の扱いについても、文書を直接変える方法と、提案を受け渡して差分レビュー (#8) に回す方法を比較した。ライブ表示を分割配置のまま残す方法と、編集面に統合する方法を比較した。

## 決定と理由

- フォルダーと設定ファイルの選択は `tauri-plugin-dialog` の OS ダイアログで行い、権限は `dialog:allow-open` のみに絞る。手入力欄は残し、どちらでも同じレジストリ呼び出しに入る。ブラウザ表示にはダイアログを出さない。
- AI 支援はサイドバーに載せ、送信範囲は操作中文書の正確な文書 ID・改訂・選択範囲とする。接続先・モデル・カスタム起動引数などの非秘密だけを保存し、秘密は OS ストアだけに置く。質問は編集せず、生成・書き換え・workspace 修正の出力は提案として受け取り、却下できる。適用は #8 の差分レビューに任せ、古い基準の提案は再確認の対象にする。#8 の隔離・提案・レビュー API は本ブランチに無いため、受け渡し口（`onProposal`）だけを用意する。
- ライブ表示は編集面に統合し、原文・分割は装飾なしの編集面のままとする。描画の装飾・水和・管路には触れず、境界面の追加 prop だけを使う。
- Vim キーは原文基準の動作を保ち、表示基準の上下・行頭末・選択は編集面に任せる。IME の未確定文は送らず、確定だけを送る。通常モードの IME キーを移動として扱わない。GUI 変更とキー入力の二重適用をしない。

## 結果・制約・確認方法

- Vitest で実ダイアログ呼び出し、AI 送信範囲、非秘密保存、提案受け渡し、キー経路を模擬 IPC で検証する。Playwright では読み取り専用・モード維持・不正入力の安全表示・操作 UI を検証し、保存成功や履歴共有は主張しない。Rust は契約一致と実 Neovim・AI・資格情報の統合で検証する。
- 未検証として残す。各 OS の実 WebView / IME におけるキー・確定・表示の確認。macOS / Linux の native compile・Neovim smoke・package 操作。実ダイアログと実フォルダーの実機操作。AI パネルの実接続と #8 差分レビュー。いずれも成功と記載しない。
