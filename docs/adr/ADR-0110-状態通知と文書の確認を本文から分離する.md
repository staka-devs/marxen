# 状態通知と文書の確認を本文から分離する

- 状態: 採用
- 日付: 2026-10-11
- 関連 Issue: #52

## 背景

保存結果や復元一覧をエディターの上に表示すると、本文とカーソルの位置が通知によって変わり、編集領域を狭める。結果の通知と利用者が判断する操作は、表示方法を分ける必要がある。

## 決定

保存成功は右下のトーストで通知し、4 秒後に閉じる。エラーと対応が必要な通知は明示的に閉じるまで残す。通知は本文のレイアウトから独立させ、フォーカスを奪わない。同じ通知が続いた場合は、新しい通知の表示時間を確保する。

未保存文書の復元、保存競合、未保存のまま閉じる確認、新規作成、名前変更はモーダルダイアログにする。復元一覧は「後で」で閉じ、メニューから再度開ける。Escape と背景クリックはキャンセル扱いとし、保存や破棄を実行しない。初期フォーカスを破棄ボタンに置かず、Tab をダイアログ内に制限し、閉じた後に元のフォーカスを戻す。

## 選択肢と理由

上部の通知領域を小さくする案でも本文の移動は残る。すべてをダイアログにする案では通常の保存まで編集を中断するため、状態通知はトースト、判断はダイアログを選ぶ。

## 結果と確認方法

エディターの位置は通知に影響されない。タイマーの更新、エラーの保持、フォーカス復帰、Tab と Escape、保存競合と閉じる確認をテストする。WebView の描画位置と OS の入力方式は各 OS の実アプリで別途確認する。
