# ADR-0166-バンドルノートとmarxenpackで画像とデータベースをまとめる

- 状態: 採用
- 日付: 2026-11-10

## 決定

- データベース表示はノート単位で有効にする。設定「データベース表示を有効にする」は許可で、ノートの frontmatter に `database: true` があるときだけ database ブロックを表にする（ADR-0163 を補う）。
- 画像やデータベースを一つにまとめたいノートは、バンドル（`名前.marxen/` フォルダー）にする。中身は本文 `index.md`、画像 `assets/`、任意の SQLite ファイルで、すべて実ファイルのまま置く。Neovim の編集・保存、Git、他のエディターはそのまま使える。
  - エクスプローラーではバンドルを 1 つのノートとして表示し、開くと `index.md` を開く。中のファイルは表示しない。
  - 新規作成（ファイル → 新規バンドルノート）は、フォルダーと `database: true` 付きの `index.md` を作る。
  - バンドルのノートに貼り付け・ドロップした画像は、画像の保存先設定より優先して `assets/` に入れる。
  - バンドルのノートの名前変更は無効にする。フォルダーごと変更する。
- 持ち運び用に、バンドルを 1 ファイル `名前.marxenpack` に書き出し、読み込める。形式は非圧縮の ustar（tar）。Marxen が自前で読み書きし、依存を増やさない。
  - 書き出しは保存済みの内容だけを対象にする。バンドル内に未保存の文書があれば拒否する。リンクとワークスペース外は含めない。
  - 読み込みは、すべての要素が 1 つの `名前.marxen/` の下にあり `index.md` を含むものだけを受け付ける。絶対パス、`..`、リンク、デバイスは拒否する。同名のバンドルは上書きせず `-1`、`-2` を付ける。フォルダーは 1 階層ずつ封じ込めを確認してから作る。
  - 上限は 256 MiB、10,000 ファイル、要素名 100 バイト（ustar の名前欄）。
- zip/tar を編集の正本にはしない。SQLite は実ファイルが必要で、保存のたびの再圧縮は失敗時にファイル全体を壊しうるため。

## 確認方法

- `cargo test --features dev-tools --lib domain::bundle_pack`（往復、危険な要素名・リンク・壊れたヘッダーの拒否）。
- `cargo test --features dev-tools --test workspace bundle_exports_and_imports_as_a_pack`（書き出し、上書き、読み込み、連番、未保存の拒否、不正な pack の拒否）。
- `npx vitest run src/domain/bundle.test.ts src/presentation/workspace/FileTree.test.tsx`。
- macOS / Linux、ネイティブの保存・選択ダイアログの見た目は未確認。
