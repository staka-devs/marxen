# 独立した複数ルートの追加と安全な削除と配置復元

- 状態: 採用
- 日付: 2026-10-15
- 関連: #57、#84、[ADR-0126](ADR-0126-文書操作をルート所有権と世代と位置で検証する.md)

## 背景

ルートID付きの文書所有権を利用し、同名のテキストや画像がある複数フォルダーを同時に操作する。フォルダー追加で既存の Neovim バッファ、未保存本文、タブ、選択を置き換えてはならない。

## 決定

- 初期の複数ルート対応は相互に独立したフォルダーに限定する。Rust がネイティブの canonicalize で別名を解決してから、重複と双方の親子関係を拒否する。単一フォルダーを開き直す操作は従来の未保存確認を維持し、追加操作と区別する。
- ツリー、クイックオープン、検索結果、テキストと画像のタブは、ルートIDと相対パスで所有者を区別する。非同期処理は取得時のルート世代を保持し、削除・置換後の応答を画面へ適用しない。検索置換はファイルの集約にも所有ルートを含める。
- 別ルートからドラッグした画像は、コピー元の登録済みルートを検証し、コピー元のルートIDと相対パスから Rust が取得したバイト列を、既存の画像貼付処理で編集中の文書のルートへコピーする。同名画像の相対パスを宛先ルートの画像と取り違えない。
- ルートを取り除くときは保存・破棄・取消を提示する。Rust は保存を選んだ全バッファの保存が成功するまで、そのルートの actor を閉じない。取消・保存失敗ではルートと全タブを保持する。複数ファイルのディスク保存自体はトランザクションではなく、途中まで保存できた場合は状態を再取得する。
- バージョン付きの配置メタデータに canonical なルートパス、ルートと相対パス付きのタブ、アクティブタブ、テキストの UTF-16 選択を保存する。Rust の未保存復旧とは分離し、本文を JavaScript の保存領域へ複製しない。
- 起動時は各ルートの新しい native 世代を取得して配置を復元する。WebView の再読み込み時は既存の native ルートとバッファを先に引き継ぐ。見つからないルートや開けないタブはメタデータに残し、旧未保存復旧を自動で破棄しない。破損・未対応バージョンのメタデータは初期の空状態で上書きしない。

## 検討した選択肢

単一の「現在のルート」を全操作に流用すると、同名ファイルを別フォルダーへ誤適用するため採用しない。親子ルートを許す場合の重複した検索・監視・保存先の規則は今回の範囲に含めない。

## 確認方法と制約

二つの一時フォルダーに同名のテキストと異なる画像を置き、実 Neovim を使う native テストで所有権、編集・保存、検索、削除の取消・保存失敗、別名の拒否を確認する。画面の状態遷移と配置の再読込は注入した transport によるテストで分けて確認する。各 OS の実 WebView・IME の確認結果は #9 の検証と区別し、実施したコマンドと未実施範囲は検証報告に記載する。
