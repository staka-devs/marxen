# 名前付きAPI接続先を安定IDと接続単位の資格情報で管理する

- 状態: 採用
- 日付: 2026-10-14
- 関連: Issue #79（関連: #7、#22、#54、#68）

## 背景

直接 API は単一プロファイル（`AiProfile` の endpoint・model 各1組）と種類単位の OS 資格情報スロット（`ai/openai-compatible`・`ai/anthropic` の3種）しか持たない。同じ通信形式の接続先を複数登録できず、endpoint・モデル・候補取得・接続結果が混同する。設定画面は「OpenAI 互換」「Anthropic」を並列ボタンで選ぶ形で、名前付き管理ができない。

## 検討した選択肢

種類スロットのまま接続先名だけを増やす方法、プロファイル JSON に秘密を含める方法、接続単位の安定 ID と接続単位の資格情報スロットに分ける方法を検討した。前二者は混同と平文保存を招くため、安定 ID による分離を採用する。

## 決定と理由

`ApiConnection { id, name, protocol, endpoint, model }` を contracts に追加する。`protocol` は既存の `openai_compatible`・`anthropic` 値を通信形式プルダウンとして再利用し、新しい wire enum は作らない。`id` は作成時に一度だけ発行する `api-` 始まりの ASCII（英数字・`-`・`_`、1–128文字）で不変とし、資格情報スロットは `ai/api/<id>` とする。ACP（codex・opencode・copilot・custom）はエージェント接続として対象外にし、Claude Code の起動・委任・実接続検証は行わない。Anthropic Messages は独立した接続先として扱う。

移行は非破壊にする。既存の `marxen.ai-profile.v1` は残し、新規 `marxen.api-connections.v1 { version, activeId, connections }` を追加する。初回のみ、選択中の旧バックエンド（endpoint が既定と異なるか model が非空の場合）に限り1件の名前付き接続を生成する。秘密の移行は Rust 内のスロット間複写コマンドで行い、IPC・JSON・ログに平文を出さない。旧種類スロットは自動削除しない。

削除は確認ダイアログで「その接続先の OS ストア資格情報も削除する」と明示し、その接続のスロットだけを削除する。他接続と旧スロットには触れない。

接続の切替は endpoint・model の一括置換として行い、実行をフェンスして接続結果・モデル候補を破棄する。モデル名の編集は選択中接続の field 更新であり、接続切替ではない。接続テスト結果は接続 ID と突き合わせて古い表示をしない。プロバイダー・モデルの表示設定（`AiViewPreferences`）と既存言語・方言カタログは維持し、新文言は en-US・ja-JP に追加して地域表現は既存フォールバックを使う。

要求経路の分離は `AiProviderConfig.connection_id`（optional）が担う。ID 付きの接続テスト・プロンプトはその ID のスロットだけを解決し、旧種類スロットへのフォールバックは一切しない。ID なしの ACP・旧単一プロファイル要求は従来どおり種類スロットを使う。ID 付き ACP は検証で拒否する。モデル候補・会話の保持は接続 ID を含むキーで分離し、双子接続（同一 endpoint・model）でも混同しない。表示設定の隠し指定は種類単位のまま維持する。

保存は正規化した全体を1回の書き込みで先に行い、失敗時は保存前の状態を保って変更を適用せず通知する。接続リストの永続化は必ず `initialized: true` を刻み、初回移行は未初期化の空リストに限り1回だけ行う。移行はリストの保存を先に確定するが、新接続の選択は鍵複写の成功まで行わない。複写の保留・失敗・空振りは旧選択を維持し、再試行ボタンを通知のそばに出す。最後の接続先の削除は空の初期化済みリストを保存し、旧単一設定を再生成しない。

モデルの表示設定は接続 ID 単位で分離する。`HiddenAiModel` に任意の `connectionId` を持たせ、照合は ID の有無まで一致した項目だけに効かせる。ACP と旧単一の種類単位の指定は従来どおり種類全体に効き、ID 付きと混同しない。チャットの接続先切替欄は安定 ID を値にし、種類単位の非表示が名前付き接続先へ波及しない。

## 結果と制約

同一形式の複数接続先が ID 単位で分離され、空・不正入力は domain 検証で拒否する。秘密は OS ストアのみに保存する。実 API の有料生成や認証変更は検証の前提にしない。各 OS の実 WebView / IME は対象外とする。

## 確認方法

移行の往復と旧設定の非破壊、接続単位スロットの分離、遅い応答の破棄、型・依存・地域化検査を対象テストと検査コマンドで確認する。広狭 UI の描画と操作は分離した headless 固定具で確認し、実 WebView / IME の確認は別途とする。
