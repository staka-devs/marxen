# ADR-0132: 全プロバイダーの管理アカウントと使用量をホストごとに分離する

- 状態: 採用
- 日付: 2026-10-16
- 関連: #103、#102

## 背景と選択肢

利用者は Codex、Claude Code、OpenCode、Devin、Gemini CLI legacy、Antigravity、OpenCode Go、MiniMax、Grok、Cursor、GLM Coding Plan の設定・認証状態・使用量を一つの画面で扱う必要がある。各サービスの CLI ログイン、契約の利用枠、API のトークン消費量は同一ではない。ブラウザーへ秘密値を永続化する方式、CLI の既定ログインをアカウント切替時に書き換える方式、未報告の利用枠を推定する方式は採用しない。

## 決定

- Rust の専用契約と application port が管理アカウントの登録・変更・選択・削除を所有する。metadata は既存の guarded atomic writer、秘密値は既存の OS 資格情報サービス `dev.staka.marxen` の専用 `ai/provider-account/<id>` namespace に保存する。API 接続の `ai/api/<id>` と CLI 既定の認証ファイルは変更しない。
- ID は Rust が発行する。保存のたびに revision を更新し、次の ACP 起動では `ProviderAccountService::launch_environment(provider, host)` の `identity` を会話キーに含め、`remove` と `set` を子プロセスへ適用する。既存の会話の起動環境を差し替えない。起動環境は IPC へ返さず、ログへ出さない。
- 管理 Codex / Claude / OpenCode / Devin は私有 HOME と provider config directory を使用する。Claude の管理起動は Linux / Windows を対象にする。Codex は file credential store を明示し、OpenCode は XDG data/config/state/cache と `OPENCODE_AUTH_CONTENT` などの認証 override を分離する。Unix のファイルは 0600、ディレクトリは 0700。Windows は保護された DACL を設定し、所有者・許可先が現在の利用者だけであることと継承規則を確認してから秘密値を作成する。管理パスの symlink を拒否する。削除は対象の私有ディレクトリと秘密値だけに作用する。
- OS ストアの失敗や metadata 書込みの失敗を握りつぶさない。metadata 保存に失敗した秘密値は元に戻す。欠けた管理資格情報や無効な選択を、システム既定へ暗黙に切り替えない。
- ローカル OS と WSL distribution は異なる選択スコープとする。WSL 用の設定は保存できるが、検証済みの bridge がないため使用量取得と起動を拒否する。macOS の管理 Claude 起動は Keychain adapter がないため拒否する。OS ストアと HTTP 使用量 adapter の対応とは区別する。
- 使用量は利用者の明示操作で取得する。Codex の既存 read-only account RPC を再利用する。ほかの対応済み adapter は固定 HTTPS endpoint のみを使い、redirect を拒否し、応答を 256 KiB、通信を 15 秒へ制限する。provider のエラー本文・URL・秘密値をエラーに含めない。
- Gemini refresh は Google の固定 token endpoint のみを使う。保存 JSON に明示された client_id / client_secret がない場合は再ログインが必要とする。既定 CLI の認証ファイルは更新しない。CLI の refresh、ブラウザー Cookie の探索・自動取込み、任意 host への Cookie 転送を実装しない。
- 認証状態は資格情報の存在確認として表示し、ログイン済み・通信成功とは表示しない。利用枠の応答は既知の形式・有限の測定値だけを表示する。欠落・不正・未知の応答は理由を返し、0% や推定の reset/残高へ変換しない。
- 公開保証のない使用量 API を使う adapter は画面で明示する。OpenCode 全体・Devin・Antigravity の使用量、は未対応である。公式ページへの導線と理由を表示し、未対応の操作を成功としない。Antigravity の `/usage` を prompt として送る実装は採用しない。

## 結果・制約・確認方法

フロントエンドへ永続化する秘密値はなく、全 11 provider が同じ保存・選択・削除 UI と host 境界を持つ。protocol/preset enum は変更しない。CLI 起動側は前述の環境 lookup と会話 identity を必ず使用する。

各 API の契約・OS 認証方式には相違がある。fixture による parser/port/UI と私有ファイルの検証を行い、実アカウント通信、各 OS の実 WebView・OS ストア、CLI 認証の実証とは区別する。対応表・入力形式・公開参照先は [provider-accounts.md](../provider-accounts.md) に記載する。

Windows の ACL は [Set-Acl の仕様](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.security/set-acl?view=powershell-5.1) に従う。固定スクリプトへパスを環境データとして渡し、OS ごとの CI で実 ACL と子ファイルの継承を検査する。

Devin は公式 `credentials.toml` を原文で私有 XDG data / Windows APPDATA へ配置し、`devin acp` の子だけで使用する。既定のログインを変更しない。
