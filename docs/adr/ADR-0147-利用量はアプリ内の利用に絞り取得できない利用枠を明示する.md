# ADR-0147-利用量はアプリ内の利用に絞り取得できない利用枠を明示する

- 状態: 採用
- 日付: 2026-10-21
- 関連 Issue: #120
- 置換元: なし（ADR-0116 / ADR-0117 の表示範囲を補う）

## 背景

使用量の表示は Codex の利用枠が中心で、他のエージェントの利用枠が出ない。また、ローカルの記録はアプリの外で使った全履歴まで混ざり煩わしい。

## 検討した選択肢

1. アプリが開始したセッション ID を記録し、それに一致する記録だけを出す。ID の永続化が必要になり、起動をまたぐと失われやすいため不採用。
2. 記録された作業フォルダーで判定する（採用）。アプリはすべてのエージェント実行を自身の作業コピー置き場（`<temp>/marxen-staging`）で行うため、そこを作業フォルダーとするセッションだけがアプリ内の利用である。起動をまたいでも判定できる。
3. Claude Code / OpenCode / Copilot の利用枠を非公式の API や画面表示から読む。公式の取得手段がなく、報告値のみを表示する方針（ADR-0116）に反するため不採用。

## 決定と理由

- 記録の走査は、Codex の `payload.cwd`、Claude の `cwd`、OpenCode の `session.directory` が作業コピー置き場（とその解決済みパス）の配下にあるセッションだけを数える。作業フォルダーが記録されていないセッションはアプリ内と証明できないため数えない。
- 見出しを「アプリ内の利用」とし、該当がない場合は「アプリ内で使った記録はありません。」と表示する。
- 利用枠は Codex を公式 RPC で表示し、Claude Code・OpenCode・GitHub Copilot は「利用枠: 取得不可」と明示する。推計値は出さない。

## 結果・制約

- 作業コピー置き場の外で同じエージェントを使った分は表示されない（意図どおり）。
- 接続テスト（一時フォルダーでの握手のみ）はトークンを使わないため対象外になる。
- 走査対象ファイル数の上限は従来どおり。

## 確認方法

- `cargo test` の `domain::transcript_usage`（配下判定・接頭辞だけ一致する兄弟フォルダーの拒否・Windows の verbatim パス）と `transcript_regression`（外部セッションの除外、OpenCode の directory 判定）。Linux コンテナ（wslc）で実施。
- `npx vitest run src/presentation/ai`（取得不可の表示、アプリ内の見出し）。
- 実機の Codex / OpenCode の記録での確認は未実施。
