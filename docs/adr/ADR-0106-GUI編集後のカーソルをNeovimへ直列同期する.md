# GUI 編集後のカーソルを Neovim へ直列同期する
- 状態: 採用
- 日付: 2026-10-10
- 関連: #21

## 背景
GUI の範囲編集は本文を更新するが、Neovim の入力位置を自動では動かさない。Enter・Escape・写像は Neovim の位置を使うため、文字入力後の本文と入力位置が一致している必要がある。

## 選択肢と決定
画面の選択変更に同期を任せる方式と、範囲編集の完了処理に組み込む方式を比較し、後者を採用する。同じ文書のキュー内で範囲編集を確定し、その revision で挿入末尾を reportCursor してから次の入力を実行する。Neovim 入力の結果が未確定の間に来た文字は、同じ native 入力経路に並べる。

CodeMirror の編集通知は選択通知より先に送り、IME の未確定文字とその選択は送らない。確定時に本文と最終選択を一度通知する。

## 結果・制約
Enter は入力した文字の末尾に作用し、直後の文字も改行後に入る。実 Neovim と revision による編集を維持する。ライブプレビューの Normal カーソルは描画済みの書記素幅を計測し、行末は既定の文字幅、Insert は細いキャレットを使う。

## 確認方法
編集・カーソル報告・native 入力の順序、Enter と直後の文字、composition の確定通知を単体で検査する。DOM Range とカーソルの位置・幅を見出し、日本語、英字、絵文字、折り返しで比較し、Windows 配布物でも入力と Enter の結果を確認する。実 OS の IME 検証は別に扱う。
