# AnyDR（あらゆる意思決定の記録）

アーキテクチャに限らず、技術、UI、製品仕様、開発手順、担当、モデル、検証、配布などの意味のある意思決定をここに残す。

## 命名と配置

- 配置先は `docs/adr/`。
- 名前は必ず `ADR-{4桁のゼロ埋め連番}-{意思決定が分かる日本語タイトル}.md`。
- 連番は既存ファイルの最大番号の次を使う。複数担当者は番号を調整する。
- AnyDR は記録範囲を表す。ユーザー指定の ADR ファイル名形式を維持する。

## 記録する内容

状態（提案 / 採用 / 保留 / 置換）、日付、関連 Issue、背景、検討した選択肢、決定と理由、結果・制約、確認方法を簡潔に記載する。過去の判断を変更するときは新しい記録を追加し、置換元と置換先をリンクする。未検証の判断はその条件を記載する。

繰り返す判断、他の担当者の作業へ影響する判断、後で理由が必要になる判断を記録する。日々の作業ログや自明な個々のコード変更は検証報告 / コミットに残す。
