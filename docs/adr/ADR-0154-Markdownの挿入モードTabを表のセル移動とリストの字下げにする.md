# ADR-0154-Markdownの挿入モードTabを表のセル移動とリストの字下げにする

- 状態: 採用
- 日付: 2026-10-22
- 関連 Issue: なし（利用者報告「挿入モードで Tab を押すと入力すらされない」）
- 置換元: なし（表のセル移動の既存仕様を補う）

## 背景

挿入モードの Tab が効かないように見えた。実アプリ（WebView2 を DevTools Protocol で操作）で再現した原因は次の3つ。

1. Neovim 0.11 は挿入モードの `<Tab>` / `<S-Tab>` に組み込みの snippet ジャンプ（スニペットがなければ素通し）を定義する。アプリはこれを利用者のマッピングとみなし、表のセル移動を行わなかった。
2. 利用者の vimrc に `inoremap <Leader>a` があり、Leader が Space のとき、Space の直後は Neovim がマッピングの続きを待つ。待機中はマッピング照会が常に真を返すため、クライアントが保持する「入力途中のマッピング接頭辞」が実際には解決済みでも残り、続く Tab が素の `<Tab>` として送られた。
3. 表やリストの中の素のタブ文字は、ライブプレビューの Markdown 描画で見えない（セル内の空白は詰められ、行頭のタブはほぼ表示されない）。

## 決定と理由

- マッピング照会で、Neovim 組み込みの snippet ジャンプは、スニペットが有効でない間は数えない。利用者自身の Tab マッピングは従来どおり優先する。
- 挿入モード Tab の判定は、クライアントの接頭辞キャッシュではなく Neovim への照会だけで行う（Neovim は本当に待機中のときだけ真を返す）。
- 対象行は表示上の選択ではなく Neovim のカーソルで決める（挿入中の入力や `o` の直後は GUI の選択が遅れるため）。
- 挿入モードの Tab / Shift+Tab は、表の中では次 / 前のセルへ移動し、リスト項目（`-` `*` `+` `1.` `1)`、タスクを含む。フェンス内は除く）では Vim の `<C-t>` / `<C-d>` で項目を字下げ / 字上げする。字下げ幅と空白かタブかは利用者の `shiftwidth` / `expandtab` に従う。それ以外は従来どおり素の Tab。

## 結果・制約

- vimrc に `expandtab` がない場合、リストの字下げはタブ文字になる（Markdown では入れ子のリストとして描画される）。

## 確認方法

- 実アプリ（開発版、利用者の vimrc）で、表の中の Tab がセル移動になること、`- k` の行で Tab を押すと字下げされることを確認。
- `cargo test --test vim_input insert_mode_tab_inserts_indentation`、`npx vitest run src/application/document src/domain/markdown-gui.test.ts`。
