# ライブプレビューの文字組みと検索操作の統一

- 状態: 採用
- 日付: 2026-10-10
- 関連: [Issue #20](https://github.com/staka-devs/marxen/issues/20)

## 背景

ライブプレビューの編集中の見出しが通常のコード文字になり、描画ブロック間にも本文と同じ高さの空行が残るため、文字の階層と余白が安定しない。ファイルとコマンドの検索には共通の選択・取消・フォーカス復帰が必要になる。

## 決定

ライブプレビューの本文と編集中の見出しには同じ本文フォントと見出しの大きさを使い、編集対象の Markdown 記号とカーソルは表示する。コードは等幅のままにする。非選択のブロック間の空行だけを小さく表示し、カーソルのある空行とコード内の空行は保持する。表示は CodeMirror の decoration で行い、文書と UTF-16 オフセットを変更しない。

タブにはファイル操作、下の行にはファイルの場所と表示モードを置く。本文は最大 760px の幅に揃え、狭い画面ではサイドバーを重ねて開き、ファイルの選択後に閉じる。

ファイル検索とコマンド検索は presentation の小さい共有 picker を使う。矢印で選択、Enter で実行、Esc と背景クリックで閉じる。閉じた時に呼び出し元へフォーカスを戻し、次に開く操作画面が先にフォーカスを取った場合は奪わない。検索を開き直す時は入力をリセットする。ファイルとタブの選択後は、確定した編集領域へフォーカスを戻す。要求は presentation の表示状態として渡し、設定などのモーダルからはフォーカスを奪わない。デスクトップの候補は開いている文書と対応する実ファイルに限定し、ブラウザーのデモ用ファイルは含めない。

設定はカテゴリごとに開き、検索だけは全カテゴリを対象にする。チャットの入力例は入力欄に入れるだけで、自動送信しない。接続先の名前と接続検査結果を区別し、未検査を接続成功と表示しない。

## 選択肢と制約

本文を再シリアライズする方式は revision と範囲編集の契約を壊すため使わない。表示用の文字組みと検索操作だけを共通化し、文書・AI 通信・保存の port と五層の依存境界は維持する。文字サイズや行間の既存設定は引き継ぐ。

## 確認方法

見出しを移動しても本文とカーソルのオフセットが変わらないこと、コード内の `#` と空行を見出しやブロック間の余白として扱わないこと、検索の選択・取消・フォーカス復帰、入力例が自動送信されないことを操作テストで確認する。ダーク・ライトと狭いウィンドウは実 WebView の描画で確認する。OS の物理キー・IME は別の検証とする。
