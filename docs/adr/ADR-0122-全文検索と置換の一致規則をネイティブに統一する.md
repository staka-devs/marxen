# 全文検索と置換の一致規則をネイティブに統一する

検索画面の補足説明は [ADR-0130](ADR-0130-全画面の補足説明を操作に必要な情報に絞る.md) で一部置換する。

- 状態: 採用
- 日付: 2026-10-14
- 関連: Issue #53

## 背景

検索、表示行での再検索、置換の範囲生成を別の実装で行うと、正規表現・Unicode・改行の扱いが分かれ、誤った範囲を編集する。独自の正規表現処理を保守する案と、描画スレッドで JavaScript の正規表現を評価する案を検討した。正しさと描画の応答性を保つため、保守されているネイティブの検索器を採用する。

## 決定

Rust の `regex = "=1.13.1"` を使用する。検索結果、プレビュー内の一致位置、置換計画を同じコンパイル済み検索器から生成する。フロントエンドはユーザー入力の正規表現を評価しない。検索オプションは大文字小文字、単語単位、正規表現の三つとし、既定値は大文字小文字を区別しない文字列検索とする。

構文は [regex 1.13.1 の一次資料](https://docs.rs/regex/1.13.1/regex/#syntax) に従う。選択、貪欲・最短反復、グループ、文字クラス、Unicode プロパティ、エスケープとインラインフラグを扱う。先読み・後読み・後方参照など未対応の構文はエラーにし、文字列への読み替えは行わない。`^` / `$` は既定で LF の各行境界に一致し、`.` は LF を除く Unicode スカラーに一致する。インラインフラグはライブラリの仕様に従う。ゼロ幅の一致も UTF-16 の挿入範囲として扱う。

大文字小文字を区別しない検索には Unicode の単純ケースフォールドを使い、正規化や複数スカラーへの展開はしない。単語単位の判定は一致の直前・直後が Unicode `\w`（Alphabetic、Mark、Decimal_Number、Connector_Punctuation、Join_Control）のスカラーでないこととする。日本語・補助平面の文字・結合文字を含む同じ規則を、文字列と正規表現の両方に適用する。句読点だけの検索に二つの `\b` を強制しない。

置換文字列は常にリテラルである。`$1` などを展開せず、空欄は削除として表示する。開いている文書は実 Neovim の本文・revision を使う。閉じたファイルも検索時の全文指紋を保持し、置換計画作成時に検証する。単一置換は選択した範囲を厳密に検証し、全件置換も検索した本文が変わったファイルを自動で読み替えない。計画の適用は文書キューとネイティブの revision 検証を通り、自動保存しない。

ルート・クエリ・オプション・アンマウントで保留中の結果と計画を無効にする。編集キューでも送信直前に有効性を確認する。置換処理は直列に実行し、既にネイティブが受理した編集は取り消したと偽らず、成功件数・ファイル数と残りの未処理を報告する。失敗・再同期後も検索を更新する。

## 上限と結果の完全性

- パターンは 4096 バイト、構文の深さは 64、問い合わせのコンパイル済み正規表現は 1 MiB、DFA キャッシュも 1 MiB。
- 1 ファイルは 1 MiB、検索した本文の合計は 32 MiB、ファイルは 2000、列挙項目は 5000。
- 表示一致は全体で 2000。単語条件を満たす一致を数え、候補は各ファイル 10000 まで。
- 注入された時計でフォルダー・ファイル・各一致の位置変換前に 2 秒を確認する。実行中の一回の読み出し・列挙・検索を強制停止する実時間保証ではない。
- プレビューは最初の行の最大 240 スカラー、一致前の文脈は最大 80 スカラー。長い一致のハイライトは表示できる部分だけを示す。

[ライブラリの計算量の説明](https://docs.rs/regex/1.13.1/regex/#untrusted-input) の通り、単一検索と反復全体の計算量は区別する。上限はバックトラック型の指数的な描画停止を避け、ネイティブでも入力・列挙・反復を有限にするための製品制約である。

打ち切り理由は共有契約で返す。表示件数を全件数と表示せず、一括置換を拒否する。打ち切り前に得た一件は、全文指紋と範囲を検証して操作できる。ブラウザの読み取り専用サンプルは別途明示した大文字小文字を区別する文字列検索だけを行い、上限と行番号を表示する。

検索と置換計画の UTF-16・行位置変換は、昇順の一致を一度の前方走査で処理する。一致ごとに全文の先頭を再走査せず、汎用の文書索引は保持しない。プレビューの行開始も同じ走査から受け取り、表示文脈の抽出を短い範囲に限定する。

## 確認方法と制約

ネイティブの一致コーパスで貪欲・選択・アンカー・Unicode・未対応構文・上限を検証する。実 Neovim のテストで UTF-16、変更済み本文、revision、厳密な単一・全件編集と未保存状態を確認する。フロントエンドでは結果の世代、編集キュー、途中失敗、展開行の移動、権威のあるハイライト、削除表示、打ち切りと App の接続を確認する。契約は Rust のエクスポーターで生成する。

各 OS の実 WebView・IME の結果は別の検証報告に明記し、単体テストやブラウザの成功から推定しない。
