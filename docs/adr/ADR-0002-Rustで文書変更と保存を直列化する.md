# ADR-0002: Rustで文書変更と保存を直列化する

- 状態: 採用
- 日付: 2026-10-07
- 関連: Issue #2, #3, #4, #8

## 背景

GUI、Vim、AI、外部ファイル変更が同じ文書を更新する。異なる位置単位や古いスナップショットに基づく編集を受理すると原文と Undo の整合性が失われる。

## 決定

Rust を Neovim RPC、ファイル保存、AI プロセスと HTTP の所有者とする。文書 ID と revision を共通 IPC 契約へ含め、文書ごとの変更を直列化する。期待 revision が一致しない編集は拒否し、最新 snapshot で再同期する。

GUI 位置は UTF-16 code unit、Neovim の列は UTF-8 byte と明示し、Unicode scalar の途中を拒否して変換する。編集は範囲パッチとし、未編集部分を再シリアライズしない。`:w` も Rust の保存経路へ委譲する。保存時にはディスクの競合を確認し、明示した解決方針だけを適用する。

AI CLI は隔離した作業コピーを変更する。差分をレビュー後、承認された範囲変更だけを期待 revision 付きで実バッファへ適用する。

## 結果

IPC 型と Rust の整合性テストが各機能の前提になる。リビジョン競合、外部更新、保存失敗、AI 差分の取消 / 却下を通常のエラー経路として扱う。
