# ADR-0142-復元済み文書を復元確認に出さない

- 状態: 採用
- 日付: 2026-10-21
- 関連 Issue: #110
- 置換元: なし（ADR-0040 の復旧記録の扱いを補う）

## 背景

フォルダーを開くと未保存文書は自動復元されるが、その後も「未保存の文書を復元」に復元済みの文書が残り、「復元する」を押すと `AlreadyExists` で失敗した。復元後も文書が未保存である限り、そのチェックポイントはクラッシュ復旧のため書き続けられる。フロントエンドで開いている文書を除外していたが、`setDocs` 直後の参照が古く除外が効かない場合があった。

## 検討した選択肢

1. 復元成功時にチェックポイントを削除する。復元後にクラッシュすると未保存の内容を失うため不採用。
2. 一覧から開いている文書の記録を除外する（採用）。記録は生きたホットイグジットのチェックポイントとして残し、復元確認には未復元の記録だけを出す。

## 決定と理由

- Rust の `Workspace::pending_recovery_entries` が開いている文書（actor が存在する ID）の記録を除外し、`list_recovery` はこれを返す。
- `recovery_entries` はディスク上の記録の在庫としてそのまま残す（保存失敗時の記録確認などで使う）。
- フロントエンドの除外は防御として残す。

## 結果・制約

- 自動復元・手動「復元する」のどちらも、成功後は一覧に出ない。「破棄する」「後で」は未復元の記録に対して従来通り使える。

## 確認方法

- `cargo test --test explorer`（復元後に `recovery_entries` は1件、`pending_recovery_entries` は0件）。
- 実デスクトップでの起動時復元の目視は未実施。
