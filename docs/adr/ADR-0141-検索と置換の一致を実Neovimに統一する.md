# ADR-0141-検索と置換の一致を実Neovimに統一する

- 状態: 採用
- 日付: 2026-10-17
- 関連 Issue: #53
- 置換元: ADR-0122（Rust `regex` による一致）

## 背景

GUIの検索タブはRustの`regex`クレート（Rust構文）で一致させていたため、Vimの記法（`\|`、`\(\)`、`\v`、`\zs`等）が使えず、`:s`や`/`とも意味論がずれていた。利用者からは検索・置換もVimに合わせたいとの要望がある。

## 検討した選択肢

1. Rust実装を維持しVim構文層を自前で載せる。Vim正規表現の再実装になり、差分が残り続けるため不採用。
2. 一致処理を実Neovimに問い合わせる（採用）。`matchbufline()`でVim正規表現の一致、`substitute()`でVim式の置換展開を行う。対象テキスト・予算・改訂検証は従来通りRustが所有する。
3. GUI入力をEx文字列に組み立てて実行する。一括置換の事前計画・改訂検証と相性が悪く、今回は見送り。

## 決定と理由

- GUI検索・置換計画の一致と置換展開は、隔離セッションの実Neovimで評価する。隔離設定のため利用者の`ignorecase`等は漏れず、大文字小文字は`\c`/`\C`接頭辞で明示する。
- 単語単位の境界判定のみRustに残す（Unicode単語文字）。`matchbufline()`が`$`を行末以外に許さないため、先読みによる境界付けができない制約による。
- 置換文字列もVim式（`\1`、`&`、`~`等）として展開する。従来のリテラル扱い（例: `$1`がそのまま入る）は`\$1`と書く。
- `g:marxen_default_shortcuts`等の利用者設定は検索セッションに影響しない。
- コマンドラインの実行結果は左タブへ反映する。`:vimgrep`/`:grep`は`QuickFixCmdPost`検知でquickfix一覧、` :s`系・`:g`系は実行報告文、`/``?`と`n`/`N`/`*`/`#`移動は`searchcount()`の現在位置を表示する。キー操作と候補計算は実Neovimが所有し、GUIは表示だけを受け持つ。

## 結果・制約

- 正規表現はVim構文。`|`単体はリテラル、`()`はリテラル、`(?=)`等は使えない。`SearchPattern`（無効なパターン）は実Neovimが判定する。
- 単語単位はVimの境界表明で処理する（`\%(^\|\W\)\zs\%(PAT\)\ze\%($\|\W\)`）。`matchbufline()`は`$`が`)`に直接続く形（例: `\%(\W\|$)`）をE53で拒否するため、`$`分岐を先頭に置く。末尾以外の一般の`$`（例: `^a$\|^b`）は正しく扱われる。
- ユーザー記法中の`$)`形も同様に`SearchPattern`として clean に失敗する（無言の誤結果にはならない）。回避は`:s`等の実Ex経路を使う。
- 1ファイル1MiB、全体32MiB、2秒予算、件数上限の枠組みは維持する。`Candidates`上限はなくなり、`SearchLimit`から削除する。
- 病的なパターンはRPCタイムアウト（15秒）で打ち切り、検索セッションを作り直す。`Time`として報告する。
- quickfix行のクリックはファイルを開いて該当行へ移動する。単発`:s`はVim自体が無言のため報告なし（改訂・本文の変化は編集画面に現れる）。
- ブラウザ表示（読み取り専用）では検索タブの従来動作のまま。実デスクトップでのTab補完・quickfix表示の目視は未実施として区別する。

## 確認方法

- `cargo test` の `domain::search`（翻訳規則）、`infrastructure::neovim::search`（実スクラッチ照合）、`workspace` の `native_search_*`（Vim意味論・予算・改訂検証）、`vim_input` の `cmdline_*`（quickfix反映・`:s`報告・`searchcount`）。
- `npm run contracts:check`（`QuickfixList`/`ExReport`/`SearchCount`追加、`Candidates`削除）と関連Vitest（SearchPanelの新規表示）。
- 実デスクトップでの目視は未実施として区別する。
