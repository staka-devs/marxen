# 対応写像を優先する挿入経路と隔離レビューでAI提案を適用する

- 状態: 採用
- 日付: 2026-10-08
- 関連 Issue: #5（基盤は #4 の文書レジストリと対応写像検査、AI 契約は #7、隔離は #8、描画は #6）

## 背景・選択肢

挿入中の文字を編集面に直接入れる方法と、対応写像の前方一致を先に調べて Neovim へ送る方法を比較した。速い連打の改訂を入力時の値で固定する方法と、直列キュー内の実行時改訂で送る方法を比較した。AI 提案を原文へ直接書く方法と、隔離複写に登録して差分承認を経る方法を比較した。

## 決定と理由

- 挿入中の印字キーは押下時点で既定動作を止め、一つの直列作業で `has_nvim_mapping` の前方一致（全体・緩衝・termcodes 正規化、入力待ち真を含む）を調べ、該当は `nvim_input`、非該当は追跡 caret の GUI 範囲挿入とする。改訂は実行時に読み、速い連打の順序と重複なしを保つ。通常・選択・演算子・命令行は常に原文基準で送り、単語・テキストオブジェクト・マクロは実 Neovim に残す。表示基準の上下・行頭末・選択は編集面に任せる。未確定文と keyCode 229 は送らず、確定だけを送る。
- カーソル反映は専用連番で行い、改訂演算の番兵は使わない。反映配送は合成を妨げず選択報告へ逆流させない。強制スクロールは行わず表示域を保つ。
- AI 送信は正確な文書 ID・改訂・選択範囲で隔離複写を登録してから行い、完了提案と送信範囲を受け渡す。差分を取得して承認・却下・取消を行い、承認だけが範囲パッチを適用する。質問は編集しない。古い基準の承認は拒否して再登録を促す。取り消した実行の確定後に複写を片付ける。
- ライブ表示は編集面に統合し、原文・分割は装飾なしの編集面のままとする。描画の装飾・水和・管路には触れない。
- IPC が無いブラウザ表示は読み取り専用に留め、保存成功や改訂増加を表示しない。

## 結果・制約・確認方法

- Vitest で対応写像の前方一致・演算子待機・速い連打の順序、隔離登録・提案・差分・承認・却下・取消・古い基準の拒否を模擬 IPC で検証する。Playwright では読み取り専用・モード維持・不正入力の安全表示・操作 UI を製品ビルド（1425 番）で検証する。Rust は契約一致と実 Neovim・隔離・マッピングの統合で検証する。
- 未検証として残す。各 OS の実 WebView / IME におけるキー・確定・表示の確認。macOS / Linux の native compile・Neovim smoke・package 操作。実ダイアログと実フォルダーの実機操作。AI パネルの実接続。いずれも成功と記載しない。
