# 開発担当のモデルと実装境界を確認して並行委任する

- 状態: 一部置換（Issue #3 の実装担当は [ADR-0016](ADR-0016-Neovimの実装担当を同じIssue内でOpenCodeへ引き継ぐ.md)、その他は採用）
- 日付: 2026-10-07
- 関連 Issue: #2, #3, #7

## 背景と選択肢

基盤の統合後、Neovim と AI 接続は並行実装できる。すべてを直列化する方法と、独立モジュールの所有者を決めて並行化する方法を比較した。OpenCode のモデルは設定ファイルだけで判断する方法と、起動したエージェントまで確認する方法を比較した。

## 決定と理由

Orca の Issue 単位の子ワークスペースで、Codex に Neovim・文書 actor、OpenCode に AI transport・認証・AI パネルを委任する。文書契約と AI 契約の生成ファイルを分け、編集・保存の所有権は Rust の文書 actor に保つ。AI と UI は revision を持つ編集提案を消費する。独立作業を並行化しつつ、共通ファイルの変更は統合時に調整する。

OpenCode は実行時の build エージェント設定と TUI 表示の両方で MuseSpark1.3 Contributor / Xhigh を確認してから委任する。指定モデルが利用できなければその担当を停止して報告し、別モデルへの変更は行わない。Claude Code は起動・委任・接続検証しない。

## 結果・制約と確認方法

- 確認済み: OpenCode 2.0.24 の build 設定は providerID `opencode-go`、model `muse-spark-1.3-contributor`、variant `xhigh`。Issue #7 の起動 TUI も `Build · Muse Spark 1.3 Contributor OpenCode Go · xhigh` を表示した。
- 通常 CLI と Orca 管理アカウントでモデル一覧が異なる場合がある。一般 CLI の一覧を起動済みエージェントの実効設定の代わりにしない。
- 各担当に単独の ADR 番号帯を割り当て、決定・検証・未検証範囲を報告させる。共有 Rust 登録・依存 lock の競合は coordinator が所有者と調整する。
- 上記は委任時の確認であり、AI 接続機能や各 OS の動作完了を保証するものではない。
