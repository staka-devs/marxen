# ADR-0119: GUIのリーダー表記と通知位置を表示設定として保存する

- 状態: 採用
- 日付: 2026-10-12
- 関連 Issue: #70

## 背景と選択肢

空白のリーダーキーが入力欄で見えず、利用者が設定を判断できない。通知の位置も利用者の作業領域に合わせて選ぶ必要がある。キー表記をそのまま Vimscript に保存する方式と、入力時に実際のキーへ変換する方式を比較した。

## 決定と理由

リーダーの空白は GUI で `<Space>` と表示し、入力された同表記は大文字小文字を問わず実際の空白1文字へ変換する。Space・バックスラッシュ・カンマ・セミコロンを選択肢にし、カスタム1文字も入力できる。他の複数文字表記やコードは従来の検証で拒否し、管理ブロックの安全な引用方式と指紋付き保存を使う。任意の Vimscript を追加生成しない。

既存管理ブロックは元のテキストの範囲を置換し、ブロック外の前後をそのまま連結する。空行だけの先頭や末尾改行のない外側の内容も保持し、ブロック内は開始標識の LF／CRLF に合わせる。管理ブロックがない場合だけ、既存テキストの終端に改行がなければ必要な区切りを追加して管理ブロックを追記する。TypeScript のプレビューと Rust の保存は同じ規則を使う。

通知位置は左上・上中央・右上・左下・下中央・右下の6値とし、既定は右下とする。表示設定の既存保存キーに追加し、旧データや不正値は右下へ正規化する。通常・エラー・復旧の通知に共通の位置を注入し、重ねる通知は選択した上下の端から内側へずらす。ポータルによる固定配置を保ち、本文のレイアウトや入力フォーカスを変更しない。

## 結果・制約と確認方法

設定画面は初期状態で全カテゴリを表示し、見出しと検索を本文のスクロール領域から分離する。狭い幅ではラベルやマッピング入力を折り返し、選択肢をテーマの文字色・背景色で表示する。Vim の再読込・管理保存・設定コード保存はスクロール中も到達できる固定操作行にまとめる。合成根は `NotificationToast.position` に `EditorPreferences.notificationPosition` を渡し、AI 表示設定は `SettingsPanel.aiVisibilitySettings` に注入する。

純粋なキー変換・Vimscript 往復、保存設定の正規化・移行・往復、仮装 gateway の送信値と指紋、通知のフォーカス維持、設定のキーボード操作、ブラウザーでの広幅・狭幅とテーマの表示を検証対象とする。仮装 gateway の成功は実 Neovim のマッピング動作や native の外部変更保護を保証せず、ブラウザーの表示は各 OS の実 WebView・IME の保証と区別する。
