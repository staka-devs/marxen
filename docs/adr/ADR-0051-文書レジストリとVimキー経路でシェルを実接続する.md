# 文書レジストリとVimキー経路でシェルを実接続する

- 状態: 採用
- 日付: 2026-10-08
- 関連 Issue: #5（基盤は #4 の文書レジストリ）

## 背景・選択肢

Issue #4 が文書レジストリ（複数文書・同一文書 ID・保存競合・外部変更・復旧・画像・設定再起動・raw grid・`nvim_input`）の IPC を提供した。Issue #5 シェル側に残っていた見本固定の単一文書状態と、フロント履歴を正本扱いする Undo 鏡像を、実レジストリ呼び出しに置き換える必要があった。Vim キー入力を CodeMirror 側で再実装する方法と、シェル層で実 Neovim へ直送する方法を比較した。

## 決定と理由

- 文書の全操作（開く・作る・改名・保存・閉じる・再読込・検索置換・復旧・画像・設定・grid・ undo/redo・カーソル・モード）を Issue #4 のレジストリ IPC だけに接続する。文書 ID はレジストリの返値を保持し、タブ切替・再開で同一 ID を使い回す。フロントは履歴を持たず、改訂は応答 snapshot のみで進める。
- 同一文書の変更系要求は文書ごとの直列キューで送る。古い改訂は再送せず、最新の snapshot を読み直して表示を置き換える。保存競合では本文を保持したまま競合表示を出し、破棄付き再読込だけが明示操作で未保存を捨てる。
- Vim キーはシェル層の key router で実 Neovim（`nvim_input`）へ直送し、マッピング・マクロ・テキストオブジェクト・演算子・コマンドラインを原文基準のまま動かす。CodeMirror 側に Vim バインドを置かず、ユーザーマッピングを上書きしない。挿入中の文字・IME 確定は範囲編集の契約で送り、未確定文は送らない。通常モードの IME キーは移動として横取りしない。
- 移動基準の選択（表示基準 / 原文基準）を設ける。表示基準では折り返し行の上下・行頭末をエディタ既定に任せ、原文基準では方向キーを含めて Neovim へ送る。
- 原文ビューは `fetch_grid` の raw redraw 更新を描画する。設定選択は `configure_document` の明示再起動で行い、本文・改訂・未保存を維持、Undo・モード初期化と評価エラーを表示する。
- IPC が無いブラウザ表示は読み取り専用に留め、保存成功や改訂増加を表示しない。
- 描画 #6 との境界面はカーソル反映の追加 prop のみとし、装飾・ウィジェット・合成処理には触れない。

## 結果・制約・確認方法

- Vitest で文書 ID・改訂の直送、直列化、stale 再同期、Vim キー写像、範囲置換、読み取り専用拒否を模擬 IPC で検証する。Playwright では読み取り専用・モード維持・不正 fixture の安全表示・操作 UI を検証し、保存成功や履歴共有は主張しない。Rust は契約一致と実 Neovim 統合で検証する。
- 未実施として残す。各 OS の実 WebView / IME におけるキー・確定・表示の確認。macOS / Linux の native compile・Neovim smoke・package 操作。AI パネルの組み込み（提供待ち）。いずれも成功と記載しない。
