# 文書レジストリとVimキー経路でシェルを実接続する

- 状態: 採用
- 日付: 2026-10-08
- 関連 Issue: #5（基盤は #4 の文書レジストリ）

複数文書の編集・保存・Undo・AI送信が同じ正本を参照するため、すべての文書操作を Rust のレジストリへ接続する。タブ切替でも文書 ID を保ち、改訂は応答 snapshot から更新する。Undo は実 Neovim の履歴を共有する。

同一文書への要求は直列化する。キー押下では同期的にキューへ入れ、実行時の Neovim モードで判断する。挿入中はユーザーマッピングを優先し、GUI 編集では正確な半開範囲を置換する。挿入モードか不確かな打鍵は推測した範囲を使わず Neovim に入力する。マクロ・テキストオブジェクト・演算子も原文基準で動かす。連続入力の投影位置は既知の本文長で切り詰めず、空文書と末尾でも入力順を保つ。

モード応答の改訂を、既知の本文の証拠として扱わない。不一致は変更を拒否して再同期する。再同期後の全文が採取した本文と完全一致する場合だけ、一度再送する。古い位置の抜粋一致だけでは再送しない。

GUI の選択は起点を保持して Neovim へ報告する。表示基準の移動も Visual モードでは Neovim に送り、ユーザーマッピングを優先する。挿入・置換中は報告した GUI の範囲を保持し、単一点しか持たない Neovim のカーソルで上書きしない。それ以外では実 Visual の範囲を取り込む。非同期の反映は文書ごとの世代で照合し、古い応答で新しい選択や入力を戻さない。IME の制御キーと未確定入力は OS に任せ、確定文字だけを編集として送る。修飾キーの形式は名前の正規化後に作り、Ctrl+方向を `<C-Up>` などとして送る。

ライブでは本文内の非アクティブな Markdown ブロックを描画し、編集対象は原文にする。カーソルは改訂と独立した連番で反映し、表示切替でも選択・スクロール・Neovim の Undo を保つ。原文ビューは Neovim の描画差分と同じ入力経路を使う。

設定変更は明示的に Neovim を再起動し、本文・改訂・未保存状態を保持する。Undo とモードの初期化、評価エラーを表示する。保存競合では本文を保持する。ブラウザ表示は読み取り専用で、保存成功や改訂増加を示さない。

確認方法は文書 ID・改訂・選択範囲・入力順序・マッピング・古い要求の拒否を模擬 IPC と実 Neovim で検証する。表示はブラウザで確認し、各 OS の実 WebView・IME・配布物の結果を検証報告に分けて記載する。
