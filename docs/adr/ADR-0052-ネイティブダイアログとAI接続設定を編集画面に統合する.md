# ネイティブダイアログと AI 接続設定を編集画面に統合する

- 状態: 採用
- 日付: 2026-10-08
- 関連 Issue: #5（基盤は #4 の文書レジストリ、AI 契約は #7、描画は #6）

## 背景・選択肢

フォルダー選択と設定ファイル選択を手入力だけに頼る方法と、OS 標準ダイアログを使う方法を比較した。AI 支援の接続先・資格情報・送信範囲・提案の扱いについても、文書を直接変える方法と、提案を受け渡して差分レビュー (#8) に回す方法を比較した。ライブ表示を分割配置のまま残す方法と、編集面に統合する方法を比較した。接続表示を初回だけ読む方法と、文書・改訂・イベントに追従させる方法を比較した。カーソル反映を改訂で重複排除する方法と、専用連番で行う方法を比較した。

## 決定と理由

- フォルダーと設定ファイルの選択は `tauri-plugin-dialog` の OS ダイアログで行い、権限は `dialog:allow-open` のみに絞る。手入力欄は残し、どちらでも同じレジストリ呼び出しに入る。ブラウザ表示にはダイアログを出さない。
- 接続表示は文書・改訂・フォルダー・イベントに追従させる。空ワークスペースは未接続、開文書ありは接続済み、異常終了はイベント経路で戻す。実行環境の有無だけでは判断しない。フッターは経路・カーソル・モード・改訂の実用表示とし、操作説明は設定画面に置く。
- カーソル反映は専用の連番トークンで行い、改訂が変わらない移動も抑止しない。改訂演算の番兵は使わない。反映配送は合成を妨げず、選択報告へ逆流させない。
- AI 支援はサイドバーに載せ、送信範囲は操作中文書の正確な文書 ID・改訂・選択範囲とする。接続先・モデル・カスタム起動引数などの非秘密だけを保存し、秘密は OS ストアだけに置く。質問は編集せず、生成・書き換え・workspace 修正の出力は提案として受け取り、差分レビューと承認を経て反映する。
- ライブ表示は本文内に描画を統合する。原文・分割は装飾なしの編集面のままとし、表示形式を変えても同じ文書と native Undo を使用する。
- Vim キーは原文基準の動作を保ち、表示基準の上下・行頭末・選択は編集面に任せる。IME の未確定文と keyCode 229 は送らず、確定だけを送る。通常モードの IME キーを移動として扱わない。GUI 変更とキー入力の二重適用をしない。
- 設定名は Rust と同じ五名称（vimrc / _vimrc / .vimrc / init.vim / init.lua）を受け付ける。
- 操作面は activity rail、タブ、抑えたツールバー、読みやすい編集幅とし、中立ダークを既定、ライトを維持する。

## 結果・制約・確認方法

- Vitest で実ダイアログ呼び出し、AI 送信範囲、非秘密保存、提案受け渡し、接続追従、キー経路を模擬 IPC で検証する。Playwright では読み取り専用・モード維持・不正入力の安全表示・操作 UI を検証し、保存成功や履歴共有は主張しない。Rust は契約一致と実 Neovim・AI・資格情報の統合で検証する。
- ブラウザ、mock IPC、実 Neovim、各 OS の実 WebView / IME、実 API 接続は別々に検証する。未実施の対象は検証報告で明示し、別環境の成功から推定しない。
