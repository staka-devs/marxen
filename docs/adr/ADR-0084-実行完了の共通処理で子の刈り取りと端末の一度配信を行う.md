# ADR-0084-実行完了の共通処理で子の刈り取りと端末の一度配信を行う

- 状態: 採用
- 日付: 2026-10-08
- 関連 Issue: #8、Epic #1
- 関連: ADR-0083 (送信範囲の完全一致と実行完了後の端末配信)

## 背景

AI 実行が成功・失敗・取消・panic のいずれで終了しても、書き込み可能な子が残っている間は隔離コピーを承認可能にしない。終了通知は一度だけ配信し、製品とテストで同じ終了処理を使う。障害注入は検証用 manager の明示設定に限定する。

## 検討した選択肢

1. 経路毎に順序を記述する / 共通処理に集約する。子の刈り取り→pin release→端末の一度配信→登録解除を `settle_production_run` に集約し、ACP・HTTP 両経路とテストが同じ関数を呼ぶ。テストは順序の写しではなく実関数を実行する。
2. HTTP の資格情報準備を pin の後に置く / 先に置く。共通の準備関数 (`resolve_http_request`) で endpoint 解決と資格情報取得を行い、欠落・不正・store 失敗は pin なしで失敗させる。権威検証は依然として通信より先である。
3. 注入を環境変数で行う / manager の明示設定で行う。`inject_apply_failure_for_tests` による文書指定の明示設定に替え、製品経路はこの値を一切触らない。環境変数の大域読み取りを製品から除去する。

## 決定

- `ai_prompt_stream` の ACP・HTTP 両 spawn は `settle_production_run` を経由する。reap は登録済み子の kill と待機 (通常時は無操作)、release は settlement 時のみ、端末は一度だけ配信する。取消要求は pin に触れない。
- `resolve_http_request` を IPC とテストで共有し、準備失敗の非 pin を検証する。利用者の資格情報は使わない。
- 適用-phase 失敗の回帰検証は明示設定の注入で行い、preflight の厳格さは保つ。

## 結果・制約

- 異常終了時も子の終了を待ってから pin を解除し、終了通知を一度だけ配信する。承認対象は終了処理後の安定した隔離コピーに限定する。
- 電源断・プロセス kill 時の保証は ADR-0040 の制約を引き継ぐ。

## 確認方法

- `cargo test --test isolation` の遅延書き込み・panic 時の刈り取り先行・HTTP 遅延端末・準備失敗の非 pin。
- `ai.rs` の端末ゲート unit と構造検証 unit。
- 各 OS の実 WebView / IME、認証済み CLI、配布後の資源配置は独立に検証し、結果は検証報告に記載する。
