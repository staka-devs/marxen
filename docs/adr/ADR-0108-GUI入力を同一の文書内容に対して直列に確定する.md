# GUI 入力を同一の文書内容に対して直列に確定する

- 状態: 採用
- 日付: 2026-10-11
- 関連: [Issue #45](https://github.com/staka-devs/marxen/issues/45)、[ADR-0106](ADR-0106-GUI編集後のカーソルをNeovimへ直列同期する.md)

## 背景と選択肢

CodeMirror は Neovim の応答を待つ間にも次の確定入力を受け取る。途中の応答で表示を置き換えると、まだ保存されていない後続入力の文書や位置が失われる。画面側で revision を推測する方式、古い revision の GUI 入力を一律に拒否する方式、確定応答と文書内容の一致を使って直列化する方式を検討した。

## 決定と理由

GUI の確定入力は変更前の文書全体、UTF-16 範囲編集、変更後の選択位置を渡す。application の文書キューは、既知の Neovim 正本文書と変更前の内容が完全一致する場合だけ、既知の確定 revision に範囲編集を結合する。Rust の応答内容も期待する編集結果と照合し、その revision に対するカーソル報告を同じキュー内で完了する。

presentation は未完了の GUI 入力がある間、途中の応答で CodeMirror の文書を置き換えない。最後の入力が完了したら最新の正本スナップショットを表示する。IME の未確定文字は送信せず、確定時の文書と選択位置を一緒に送る。

## 結果と制約

revision の生成は Rust と Neovim に限る。外部変更などで文書内容が一致しない場合、範囲を再利用せず正本を再取得して競合を通知する。AI の提案や既存の厳密な revision 付き編集には、この GUI 入力の結合規則を適用しない。

## 確認方法

遅延した複数の GUI 応答、サロゲートペアを含む選択位置、確定入力後の Enter、Neovim の Undo、外部変更の拒否、composition の単一送信を検証する。CodeMirror のテストと配布版の実 WebView・Neovim 検証を区別し、各 OS の実 IME は実際に操作した場合だけ検証済みとする。

挿入モードの通常の英字も CodeMirror に即時表示し、キーの識別情報と変更前の全文を同じ確定キューへ渡す。確定時には実 Neovim のモードと挿入マッピングを先に確認し、マッピングがある場合は Neovim にキーを渡す。日本語・絵文字と英字が続いても、表示されていない英字をまたいだ古い範囲を再利用しない。

改行などの native キー操作が未確定の間に続く確定文字は、古い GUI 範囲ではなく入力キーと同じく直列キューの Neovim カーソルへ渡す。実行時のモードが挿入・置換以外、またはリビジョンが外部変更でずれた場合は再同期し、通常モードのコマンドとして解釈しない。IME の未確定文字は引き続き送信しない。カーソルの GUI 反映は描画前に行い、native モード表示は同じ世代のカーソルを取得後に更新する。

IME の native カーソル所有は変換開始時に捕捉して確定まで保持する。貼り付けも通常は変更前の全文を検査し、native 操作直後に捕捉したものは実行時のカーソルを取得して挿入する。画像の挿入は既存の厳密な revision 検査を保つ。

GUI 編集の検証エラーは競合へ置き換えず、元の拒否理由を表示し、最新の native snapshot とカーソルへ戻す。同一の文字列・revision でも拒否後の snapshot の同一性を GUI 同期に使い、楽観的な表示だけが残ることを防ぐ。

正本文書とカーソルが同時に更新されたときは、描画前に正本文書を反映してからカーソル位置を適用する。変更前の短い文書に対して位置を切り詰めたまま確定しない。
