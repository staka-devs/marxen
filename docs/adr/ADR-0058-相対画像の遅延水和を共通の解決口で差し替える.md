# 相対画像の遅延水和を共通の解決口で差し替える

- 状態: 採用
- 日付: 2026-10-08
- 関連 Issue: #5（描画は #6、基盤は #4 の相対画像読込）

## 背景・選択肢

読覧と live 小部品で相対画像の解決が別々に残り、遅延到着が古い表示に載る恐れがあった。管路内で絶対化する方法と、表示層の解決口に残す方法を比較した。解決を待たずに貼る方法と、中止・分離・源泉変化で捨てる方法を比較した。

## 決定と理由

- 相対画像の解決は UI 層の `resolveImage(src, signal)` に集約し、Rust の作業場読込（収容・ symlink・種別検査）に裏打ちする。管路は相対源泉を verbatim に保ち、file 偽装や live 絶対路を作らない。到着は data 画像 URL のみを許し、方式外は表示しない。
- 読覧は結果確定の中止周期で、live 小部品は小部品の中止・破棄周期で水和する。既に中止なら遅延導入前に同期復帰し、遅延・中止・分離・源泉変化の結果は捨てる。Unicode 復号と方式許可表で日本語名を扱い、失敗は代替文のままとし、偽の内容を注入しない。
- 秘密は扱わず、localStorage に置かない。殻の手動水和は除き、管路に触れない。

## 結果・制約・確認方法

- Vitest で相対判定・Unicode 復号・安全方式・遅延入替・遅延破棄・中止短絡を検証する。Playwright では不正入力の安全表示を製品ビルド（1425 番）で検証する。Rust は収容・ symlink・種別の統合で検証する。
- 未検証として残す。各 OS の実 WebView における画像表示の確認。実機の結果を browser の成功から推定しない。
