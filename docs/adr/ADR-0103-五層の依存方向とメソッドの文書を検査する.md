# 五層の依存方向とメソッドの文書を検査する

状態: 採用。日付: 2026-10-09。関連: #14、#15、#18、#19。五層への実装移行は回帰・依存検査で確認する。

## 背景と選択肢

文書・保存・AI のユースケースが OS・通信・画面の具体実装を直接参照すると、責務と変更の範囲が広がる。ファイルの移動や公開名の転送だけでは、この依存は解消しない。利用する境界を定義して具体実装を注入する方式と、既存の具体実装への依存を維持する方式を比較した。

## 決定と理由

Rust と TypeScript の製品コードを次の五層へ置く。

| 層 | 所有するもの | 参照できる層 |
| --- | --- | --- |
| contracts | 副作用のない共通型・IPC の schema | contracts |
| domain | 範囲・座標・文書・会話等の純粋な規則 | domain、contracts |
| application | 編集・保存・AI・隔離のユースケース、利用する小さい port | application、domain、contracts |
| infrastructure | Neovim、fs、HTTP / ACP、資格情報、clipboard、プラットフォーム API の adapter | infrastructure、application、domain、contracts |
| presentation | React / CodeMirror / DOM の画面、Tauri コマンド・画面通知 | presentation、application、domain、contracts |

composition root で具体実装を組み立てる。Rust は `lib.rs` / `main.rs`、TypeScript は `App.tsx` / `main.tsx` と明示した composition モジュールを使う。内側から composition root を参照しない。infrastructure と presentation の直接依存は置かない。契約型を複製して名前だけを変えることは避ける。

port は現在のユースケースが必要とする操作に限定する。利用しない拡張基盤や汎用 DI framework は追加しない。既存の具体実装とテストの差替えで、その操作・エラー・取消・終了順序の契約を検証する。

すべての手書きの名前付き関数・メソッドに Rustdoc / JSDoc を付ける。公開・非公開、constructor、trait・interface の操作、関数値の明示的な定義、テスト補助・配布スクリプトも対象とする。目的、引数の単位、結果、副作用、競合や取消の条件を必要な範囲で説明する。匿名 callback と生成物・外部資源は対象外。

## 制約と確認方法

`npm run architecture:check` を手動検証と CI へ組み込む。TypeScript AST と解決した import / browser global、Rust の use tree / 名前空間 / outer Rustdoc を検査する。型だけの import、別名・まとめた import、非公開・ローカルな操作も対象にする。生成物は generator header で区別する。

この検査は import と文書の欠落を防ぐものであり、SRP・LSP・OCP の全面的な証明ではない。責務・実装の置換契約・重複・不要な抽象はコードレビューと既存の振る舞いの回帰で確認する。実 Neovim 正本、revision 付き範囲編集、保存・Undo、取消・pin 解放・credential の非公開を維持する。OS の実 WebView / IME の検証結果は別に記録する。
