# ADR-0115: フロントエンドの言語切替と地域表現のフォールバック

- 状態: 採用
- 日付: 2026-10-12
- 関連 Issue: #60

## 背景

画面の日本語文言が部品、通知、入力検証、アクセシビリティ名に分散していた。文書・選択・未保存編集・実行中のチャットを保持して表示言語だけを切り替える必要がある。地域表現は利用者の明示選択に限る。

## 検討した選択肢

独自の文字列検索と Intl の組み合わせも検討した。補間と複数形の処理には継続的な検証が必要になるため、成熟した i18next にその責務を持たせ、利用側のキーとパラメーターを共有型で検査する。

意味を表す識別子をキーにする方法と、元の日本語をキーにする方法を比較した。既存文言との対応が直接確認できる後者を採用する。通知の状態には翻訳済み文字列を保存する方法もあるが、表示中の言語変更に追従できるメッセージ記述を採用する。

## 決定

`en-US` と `ja-JP` を完全な基本カタログとし、`ja-JP-x-kansai` と `ja-JP-x-tokushima` は少数の文単位のオーバーレイとする。大阪の現代的な日常表現、徳島市・鳴門周辺を基準にする。未定義の地域訳は `ja-JP` にフォールバックし、短い技術ラベルと曖昧な文は標準日本語を使う。エラーの案内は標準日本語を保持する。

gettext と同様に元の日本語メッセージをキーとして扱い、元のリテラル型から補間のキーと必須パラメーターを導出する。基本カタログのキー・補間値の一致を型検査とカタログ検査で確認する。i18next 26.4.3 は公式 npm registry の安定版と公式の複数形・型付け資料を確認して採用した。ロケールごとに独立したインスタンスを作り、英語の複数形と数値には基本言語の Intl 規則を使用する。

contracts がカタログと共有型、domain がロケール選択・検証規則、application が保存ポートと選択ユースケース、infrastructure がブラウザ保存と i18next 実装を所有する。composition が具体実装を注入し、presentation が React context で表示を更新する。domain の入力検証とエラー説明は翻訳関数を引数で受け取る。Rust のコード・詳細・パスは維持し、構造化されたエラーの説明を画面側で翻訳する。

選択言語は `marxen.language` に保存する。未選択時はホストが報告する主言語が日本語なら `ja-JP`、それ以外は `en-US` とする。ブラウザ / WebView の `navigator.language` は infrastructure の source が読み、composition で注入する。ホストの地域タグから方言を自動選択しない。未対応の日本語私用タグは標準日本語へ戻す。Intl の locale には `en-US` または `ja-JP` を使う。

Context の更新でエディターのキーを変更しない。CodeMirror の属性とライブプレビュー拡張は Compartment で再設定し、本文・選択・エディターインスタンスを保持する。プレビューのキャッシュは表示言語を含む。通知や画面の文言を翻訳し、利用者の本文、AI 応答、ファイル名・パス、コマンド、vimrc の設定名は翻訳しない。DOM の既存テキストを走査・置換しない。

## 地域訳の根拠と制約

[国立国語研究所の解説](https://kotoba.ninjal.ac.jp/qa/yokuaru/qa-232/)の大阪と東京の用法差を踏まえ、方言を一律の語尾変更として扱わない。関西版の保存完了・自動保存の告知は、[南早葵「大阪方言における文末詞デの用法とイントネーション」](https://ir.library.osaka-u.ac.jp/repo/ouka/all/86406/sln18-071.pdf) pp.72–74 の聞き手への情報提示の記述を参考にした。イントネーション次第で非難などの意味が加わるため、エラーへの適用は避ける。

阿波版の「保存できたで。」は [鳴門市の方言](https://library.bunmori.tokushima.jp/digital/webkiyou/61/149-160.pdf) pp.151–152 の文末詞「デ」の告知の用法を参考に、成功結果を知らせる場面に限って選んだ。徳島市・鳴門を含む地域内にも差があり、「ケン」「ケンド」や「ジェ」「ジョ」を他の通知へ広げない。[徳島大学の地域紹介](https://www.tokushima-u.ac.jp/fs/5/2/7/4/1/_/tokushuu135.pdf) p.4 の類似語の意味差も考慮し、曖昧な表現は標準日本語とする。

これらは資料に基づく文脈の判断であり、UI 訳そのものの地域話者によるレビューを実施したという主張ではない。話者・世代・イントネーションの差は文字の UI だけでは表現しきれない。

## 確認方法

型検査、カタログのキー・補間・空メッセージの検査、保存設定の再生成、実 CodeMirror の同一インスタンスと編集・選択の保持、英語の設定・aria 表示、実行中のチャットが停止・再送されないことを対象テストで確認する。各 OS の実 WebView と IME の検証はブラウザや jsdom の成功から推定しない。
