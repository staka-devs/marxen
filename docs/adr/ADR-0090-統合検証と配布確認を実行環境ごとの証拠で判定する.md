# ADR-0090: 統合検証と配布確認を実行環境ごとの証拠で判定する

- 状態: 採用
- 日付: 2026-10-08
- 関連 Issue: #9

## 背景と選択肢

Rust の実 Neovim 回帰、Chromium の UI 回帰、OS 固有の WebView・IME、配布 package の生成・起動は異なる経路を検証する。ブラウザや一つの OS の成功を他の経路の成功と扱う方法では、入力と資源配置の不具合を見落とす。

## 決定と理由

CI は Windows x64、macOS arm64 / x64、Linux x64 の native runner で実行する。各 target で固定 SHA の Neovim 一式を同梱して native runtime smoke を実行し、文書・AI・隔離の3種類の Rust / TypeScript 契約を照合する。Rust test・fmt・clippy、TypeScript check・unit、製品 build とライブ harness の E2E、未署名 package 生成を検査する。package artifact が存在しない場合は失敗とする。

検証報告は実行したコマンド、対象 commit、環境、結果を示す。headless Neovim、mock AI、Chromium、実 native WebView、実 IME、package の生成・資源確認・起動、署名・公証を区別し、未実施は未実施と記載する。opt-in の OS 資格情報テストは使い捨て entry のみに限定し、既定の成功を OS ストアの検証と数えない。

## 結果・制約と確認方法

配布版は署名資格情報がない環境では未署名で生成する。4つの native CI 設定だけでは実行成功を証明しない。各 OS の実 WebView / 日本語 IME と配布後の操作は対応実機で別途確認する。最終報告は `docs/reports/issue-9-integration.md` に置き、CI の実行結果とローカルの実測を区別する。
