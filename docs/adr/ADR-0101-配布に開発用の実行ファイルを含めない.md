# 配布に開発用の実行ファイルを含めない

- 状態: 採用
- 日付: 2026-10-09
- 関連 Issue: #9、#15

## 背景

製品に必要な実行ファイルは Marxen と同梱 Neovim である。契約型の生成器や独立したプロトコル検証用 fixture は、開発・検証専用であり配布に含める必要がない。

## 決定と理由

5 つの契約生成器・fixture binary を、既定で無効な `dev-tools` feature によって制限する。Tauri の通常ビルドは製品用の `desktop` のみを使用する。契約生成の npm script と CI の Rust test / 全 target の Clippy は `dev-tools` を明示して、検証範囲を維持する。製品用の `cargo check` は既定 feature のまま確認する。

別 crate や独自の配布用削除処理は増やさず、Cargo の [required-features](https://doc.rust-lang.org/cargo/reference/cargo-targets.html#the-required-features-field) と Tauri が対応する binary 選択を用いる。

## 制約と確認方法

開発・テストでは `--features dev-tools` が必要となる。README と CI のコマンドを一致させる。実 package を展開して、生成器と fixture が含まれず、Marxen と完全な Neovim runtime が存在することを確認する。Rust / 契約 / 全 target の Clippy は開発用 binary を含めて実行する。
