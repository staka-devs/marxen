# 上部メニューと単一ルートの文脈操作を共有コマンドに集約する

- 状態: 採用
- 日付: 2026-10-14
- 関連: Issue #57、[ネイティブ編集メニュー](ADR-0121-常設の書式操作とVim状態を検証する編集メニュー.md)

## 背景と選択肢

フォルダーを開く操作とツリー内の作成操作がエクスプローラーに混在し、パレットや追加操作にそれぞれの実行条件がある。操作を各表示から直接実装する方法と、実装済みの文書・ワークスペース所有者に共通のコマンドで委ねる方法を比較した。

## 決定と理由

上部にファイル・編集・選択・表示・移動・ヘルプのコンパクトなメニューを設ける。フォルダー選択と絶対パス入力はファイルメニューに置く。エクスプローラーは階層、種類別アイコン、相対パスに対する文脈操作と更新に集中させる。メニュー・パレット・ワークベンチのショートカット・ツリー文脈操作は共有ディスパッチャーを消費し、表示時と実行時に能力を確認する。利用できない操作も理由付きで表示する。

作成・名前変更は操作時に取得したルート世代と相対パスを保持する。フォルダー作成は既存のRust処理を呼び、文書バッファを開かない。Markdownの名前変更は文書IDと取得済みrevisionを用い、文書キューから既存のネイティブ処理に渡す。更新は文書本文や未保存状態を置換せず、古いルート世代の結果を破棄する。

編集と全選択は実Neovimの状態とrevisionを使う。ブラウザ履歴・独立したclipboard・仮のVimキー列は追加しない。全選択は文書キューでnativeのモード・選択を再確認し、同じrevisionの正本に対して既存のカーソル処理を呼ぶ。矩形選択・command-line・terminalと、文書でない入力欄を対象外とする。

この変更は単一ルートを扱う。複数ルートは別の仕様・実装とし、ルートIDと相対パスが文書、保存、検索、画像、復旧、AI対象まで伝播することを条件にする。単一ルートの状態を配列で包む実装は採用しない。フォルダー・画像・一般テキストの名前変更やファイルの切り貼りも、対応するネイティブ処理を実装するまでは提供しない。

## 結果・制約と確認方法

メニューは矢印・Enter・Escapeとフォーカス復帰、ツリーは可視行のroving focus、階層移動、F2・Menu・Shift+F10と右クリックを備える。アイコンには操作名を付け、狭い幅でもドロップダウンとダイアログを画面内に配置する。

文書とルートの世代、遅延更新、無効操作、名前変更のID・revision、Unicodeのnative選択、翻訳、焦点復帰をunitで検証する。実際のシェルを模擬transportに接続したブラウザfixtureで幅・表示・操作を確認できるが、各OSのWebView・物理IME・native clipboard・Neovim・ファイルシステムの確認は独立した受け入れ条件とする。
