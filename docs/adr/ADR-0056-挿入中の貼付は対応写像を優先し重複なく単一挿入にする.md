# 挿入中の貼付は対応写像を優先し重複なく単一挿入にする

- 状態: 採用
- 日付: 2026-10-08
- 関連 Issue: #5（基盤は #4 の文書レジストリと対応写像検査）

## 背景・選択肢

貼付事象より後の非同期読取に頼る方法と、貼付事象の clipboardData を同期的に読む方法を比較した。貼付点を常に caret 扱いする方法と、正確な半開選択範囲を第一編集に使う方法を比較した。古い改訂で却下された範囲を自動再送する方法と、対応確認が取れる場合のみ一度だけ再送する方法を比較した。

## 決定と理由

- 貼付は貼付事象を先に受け、本文と画像バイトを同期的に読み、既定挿入の前に止めて一度だけ送る。読取文の往復は行わない。キーボード Ctrl+V は挿入方式の `<C-v>` 明示写像を先に調べ、該当は原文入力、非該当は正確な半開範囲の単一置換とする。メニュー貼付は対応写像を模さず直接挿入する。通常方式の Ctrl+V は原文の矩形選択として残し、その本文半は捨てて二重化しない。
- 第一編集は選択範囲（正順・逆順の min/max、Unicode と改行の span を含む）を置換して崩し、速い連打は崩した caret を進めて順序を保つ。画像は第一書類を選択範囲に置き、後続は挿入済み Markdown の直後に連ね、同一 offset を再利用しない。
- 新しい改訂で却下された範囲は自動再利用しない。最新 snapshot の本文が採取全文と完全一致する場合のみ、切り詰め範囲で一度だけ再送する。抜粋の一致だけでは足りず、一致しない場合は stale として示す。画像書込は再送しない。対応写像の読取不能は黙って GUI 挿入に落とさず誤りとして示す。
- ブラウザ表示では読取専用に留め、貼付の成功や改訂増加を表示しない。

## 結果・制約・確認方法

- Vitest で明示写像ありは原文送りのみ、写像なしは選択範囲の単一置換、メニュー直接挿入、画像の単一性と連鎖 offset、古い範囲の対応付き単一再送と不一致の表面化、読取不能の閉鎖失敗を模擬 IPC で検証する。Playwright では読取専用と改訂不変を製品ビルドで検証する。Rust は対応写像と実 Neovim の統合で検証する。
- 未検証として残す。各 OS の実 WebView における貼付・画像・表示の確認、実 IME の確定の確認。実機の結果を browser の成功から推定しない。
