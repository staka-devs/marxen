# 挿入中の貼付は対応写像を優先し重複なく単一挿入にする

- 状態: 採用
- 日付: 2026-10-08
- 関連 Issue: #5（基盤は #4 の文書レジストリと対応写像検査）

## 背景・選択肢

実際の保存・GUI Undo・保存で原文が316バイトに復帰する一方、貼付の重複が残っていた。挿入中の Ctrl+V を無条件の原文入力として送る方法と、明示の対応写像を先に調べて振り分ける方法を比較した。既定貼付を許す方法と、先に既定を止めて直列の一挿入にまとめる方法を比較した。

## 決定と理由

- 挿入・置換中の Ctrl+V は押下時点で既定を止め、一つの直列作業で挿入方式の `<C-v>` 明示写像を調べ、該当は原文入力として送り、非該当は読取文を単一の GUI 範囲挿入とする。追跡 caret を同期的に進め、続く DOM 貼付は時刻番兵で抑止し、重複を出さない。通常方式の Ctrl+V は横取りせず、原文の矩形選択として残す。
- 改訂は実行時に束ね、stale では最新 snapshot に再同期して一度だけ再送する。適用なしの却下は再送しても重複しない。絵文字・日本語・改行を含む読取文を一挿入として扱う。
- ブラウザ表示では読取専用に留め、貼付の成功や改訂増加を表示しない。

## 結果・制約・確認方法

- Vitest で明示写像ありは原文送りのみ、写像なしは単一範囲挿入、通常方式は写像検査なしの原文送り、DOM 貼付の重複なしを模擬 IPC で検証する。Playwright では読取専用と改訂不変を製品ビルド（1425 番）で検証する。Rust は対応写像と実 Neovim の統合で検証する。
- 未検証として残す。各 OS の実 WebView / IME における貼付・確定・表示の確認。実機の結果を browser の成功から推定しない。
