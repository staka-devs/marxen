# ADR-0004: 開発をIssueとOrcaの依存関係で管理する

- 状態: 採用
- 日付: 2026-10-07
- 関連: Issue #1–#9

## 背景と選択肢

初期版は Neovim、保存、GUI、描画、AI の契約を共有する。ひとつの未整理な変更にまとめる方法と、Issue ごとに受入条件 / 依存 / 担当を明示する方法を比較した。ユーザーの計画は後者と Orca による進捗管理を指定している。

## 決定と理由

GitHub の Epic #1 と子 Issue #2–#9 で要件を追跡する。Orca 1.4.221 の同じインストールから CLI / orchestration ガイドを取得し、Run と Dispatch を管理する。Issue 単位の子ワークスペースとブランチを使い、依存する契約を確定してから次を開始する。Codex と OpenCode が相互レビューし、CI とレビューが通ってから統合する。

## 結果と確認

Orca の起動 / 接続状態、Dispatch の実効 launcher、テスト結果、commit / PR と Issue の関連を記録する。入力の受付や heartbeat を完了とは扱わない。完了通知の受理後に worker の解放または次の担当を決める。
