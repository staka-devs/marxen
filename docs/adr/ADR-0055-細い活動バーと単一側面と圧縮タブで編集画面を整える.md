# 細い活動バーと単一側面と圧縮タブで編集画面を整える

- 状態: 採用
- 日付: 2026-10-08
- 関連 Issue: #5（描画は #6、隔離は #8、基盤は #4）

## 背景・選択肢

本文のための広い領域を確保し、Obsidian / VSCode に近い落ち着いた編集画面にする。操作を常時並べる構成と、用途別のパネルやメニューへ収める構成を比較し、後者を採用する。

## 決定と理由

- 細い活動バー（約44px、探索・検索・ outline・AI・設定）と用途切替の単一側面、約34-38px の圧縮タブ、単一編集面、約22px の最小状態バーを用いる。冗長な操作行と常時表示の経路入力を除き、手入力の経路欄は折り畳みとする。
- 視点は 100dvh 固定とし、各面が独立にスクロールし、頁全体の縦伸びを作らない。巨大な札様式をやめ、編集面を幅いっぱいに保つ。明・暗の対比主題を保つ。
- 描画 #6 との境界面は livePreview 真偽値と連番付きカーソル反映だけとし、装飾・水和・管路には触れない。原文ビュー・検索置換・ outline・命令面・設定は集約面に収める。

## 結果・制約・確認方法

- Vitest で文書 ID・改訂・直列化・ stale 再同期・読み取り専用拒否を模擬 IPC で検証する。Playwright では製品ビルド（1425 番）で読取専用・方式維持・不正入力の安全表示・操作 UI・細幅での利用可・頁縦伸びなしを検証し、1493×1047 と 1280×800 の清掃撮影を残す。
- 各 OS の実 WebView / IME とネイティブ配布物は別に検証する。ブラウザの成功から実機の成功を推定せず、結果は検証報告に記載する。
