# ADR-0096: エージェントチャットとインライン会話の履歴管理

- 状態: 採用
- 日付: 2026-10-08
- 関連 Issue: #13
- 対象: Agent チャット、インラインチャット、AI IPC v2、隔離レビュー連携

## 背景

選択範囲に対する短い編集指示と、文書を参照して続ける会話を両方提供する必要がある。会話履歴、Vim のキー操作、送信範囲、応答の取消を一貫して扱い、接続先を変えても以前の履歴を別の提供者へ送らない。

## 検討した選択肢

- Rust 側に会話ストアを持つ: 永続化と取消競合が増えるため見送り。
- 履歴を持たない単発送信のままにする: 多ターン作業ができないため見送り。
- 履歴を上限付きの要求として運び Rust が検証する: 採用。ACP は送信ごとにセッションを開始し、完了した会話を指示の前文として渡す。継続セッションの再開 API は公開しない。

## 決定

- `PromptContext.text` は登録範囲の抜粋そのものとする。Rust は Neovim の同じ範囲と一致するか検証する。Agent は選択がないと現在のファイル全体、インラインは選択または現在の段落を対象とし、どちらも対象ファイルと内容を表示する。

- 完了した利用者・AI の一組だけを送信履歴へ含める。失敗・取消・未完了のやり取りは含めない。接続先やモデルを変更した会話は分離し、以前の会話は閲覧できる。空の会話の設定変更では会話を増やさない。
- Tauri の要求が実行 ID を返す前に届くイベントは上限付きで一時保持し、その ID に一致する応答だけを届ける。完了・失敗・取消でイベントの購読を解除する。
- 会話切替やインラインの閉鎖は古い応答を遮断する。実行開始が遅れて完了した場合もその処理を停止し、停止が確定するまで共有の作業コピーを他のチャットへ渡さない。共有コピーの所有者は同期的に確保する。
- インラインチャットは編集位置の近くへ配置し、画面端で位置を調整する。ショートカットはエディターの Vim 入力より先に処理し、閉じると本文へフォーカスを戻す。接続設定は設定画面から展開できる。
- AI の完了した回答も共通の Markdown 描画経路を使う。差分には対象ファイル名を表示し、内部 ID や文字オフセットを操作画面に出さない。

- Agent チャットを右サイドバーの会話 UI とする。会話ごとのメッセージ、複数ターン履歴（HTTP 含む）、会話一覧/選択、新規会話、送信/受信/取消/再試行/エラーを扱う。サイドバー非表示でも aside を常駐させ transcript と staging を保持する。新規は既存会話を selector に残し、秘密を含めない。
- 提供者設定・資格情報・接続テストは折りたたみの設定領域または exported 設定コンポーネントに置き、`openSettingsToken` の増加で外部（SettingsPanel の AI 設定入口）から展開できる。
- インラインチャットは Ctrl+Shift+I / Cmd+Shift+I で選択または現段落を対象に開く。素の Ctrl+I は Vim の進む/Tab として素通しし、奪取しない。パレットと可視ボタンからも開ける。Agent とは別会話で正確な基準文脈を保持する。入力欄は自動 focus、Escape は取消して閉じる。
- 送信時に隔離コピーを自動登録する。staging prop があっても毎回 ensure で正確な範囲を検証し、一致するときだけ再利用する。一つの共有 slot に対して Agent とインラインは相互に送信を抑止し、実行中の所有コピーを失わない。
- 実行は一つの token で管理する。取消は staging 待ちや start 待ちでも効き、遅れて届いた handle は破棄する。完了前の start 解決でも spinner を残さない。完了は捕捉した mode と文脈で報告し、reset・会話切替・提供者変更・unmount は旧実行を遮断して提案を出さない。再試行は捕捉した入力と文脈を使い、失敗/取消ターンを履歴に入れない。HTTP 送受信の待ち受けは取消ポーリングと競合させ、無応答サーバーでも client timeout を待たずに取消が勝つ。
- 質問の回答は会話へ表示する。編集指示の回答は Rust の隔離コピーへ取り込み、差分の確認と承認後に文書へ反映する。取り込みに失敗した場合だけ再取り込み操作を表示する。
- 履歴は完了ターンのみを古い順に最大 32 件、各 1〜20000 文字として Rust が検証する。取消・失敗ターンは次要求に残さない。提供者ごとの資格情報は分離する。
- 表示は平坦で compact な VSCode 風とし、transcript が sidebar を満たし、composer を下部固定、参照をファイル名 chips、対象抜粋を表示する。内部の文書 ID・コピー ID・UTF-16 offset は表示せず、revision は tooltip に寄せる。「ワークスペース編集」の表記に統一する。

## 結果・制約

- AI IPC は schema version 2。`history` 既定空配列のため旧 JSON は読める。
- 既存の revision、UTF-16、隔離、stale 却下、undo、取消 cleanup、端末順序を維持する。
- 資格情報は OS ストアのみで、画面・要求本文・ログに値を含めない。
- 実 API 接続の有無は mock 成功から推定しない。

## 確認方法

- Rust の単体・統合テストで履歴の境界、HTTP の複数ターン、ACP への履歴合成、初回応答後の取消、無応答サーバーの取消を検証する。模擬サーバーの待ち受けにも期限を設ける。
- UI テストで遅延開始、取消、アンマウント、接続先の変更、会話選択、非表示中の保持、ショートカットと Vim 入力の共存、範囲送信と差分適用を検証する。
- 実 WebView から Rust を通して模擬 ACP プロセスを起動し、返信、取消、対象範囲への適用、一回の Undo を確認する。実施結果と未検証の範囲は統合検証報告に記載する。
