# ADR-0096: エージェントチャットとインライン会話の履歴管理

- 状態: 採用
- 日付: 2026-10-08
- 関連 Issue: #13
- 対象: 右サイドバー Agent chat、インライン chat、AI IPC v2、隔離レビュー連携

## 背景

単発の AI パネルでは複数ターンの文脈が残らず、送信前の手動登録が必須だった。選択編集と Agent 作業の会話が混在し、HTTP 接続先の履歴所有も曖昧だった。

## 検討した選択肢

- Rust 側に会話ストアを持つ: 永続化と取消競合が増えるため見送り。
- 履歴を持たない単発送信のままにする: 多ターン作業ができないため見送り。
- 履歴を明示の bounded 要求として運び Rust が検証する: 採用。ACP は既存セッション扱いを維持し、同一ターンを prompt 前文として受け取る。

## 決定

- Agent chat を右サイドバーの会話 UI とする。会話ごとのメッセージ、複数ターン履歴（HTTP 含む）、新規会話/リセット、送信/受信/取消/再試行/エラーを扱う。提供者設定・資格情報・接続テストは折りたたみの設定領域または exported 設定コンポーネントに置き、`openSettingsToken` の増加で外部から展開できる。
- インライン chat は Ctrl+I で選択または現段落を対象に開く。エディタ近傍に固定し、指示と streaming 応答、明示の差分確認操作を持つ。Agent とは別会話で正確な基準文脈を保持する。
- 送信時に隔離コピーを自動登録する。手動の事前登録儀式を強制しない。一致する登録があれば再利用し、異なる場合は置換する。
- AI 出力は提案テキストのままとし、既存の Rust 隔離/revision 承認フローを経る。原文への直接書込はしない。
- 履歴は完了ターンのみを古い順に最大 32 件、各 1〜20000 文字として Rust が検証する。取消・失敗ターンは次要求に残さない。
- UI は平坦で compact な VSCode 風とし、transcript が sidebar を満たし、composer を下部固定、参照を小 chips、操作を日本語 label の icon 動作にする。

## 結果・制約

- AI IPC は schema version 2。`history` 既定空配列のため旧 JSON は読める。
- 既存の revision、UTF-16、隔離、stale 却下、undo、取消 cleanup、端末順序を維持する。
- 資格情報は OS ストアのみで、画面・要求本文・ログに値を含めない。
- 実 API 接続の有無は mock 成功から推定しない。

## 確認方法

- `cargo test --lib ai` 32 件通過（履歴境界・HTTP body 2 ターン・ACP 合成を含む）。
- `cargo test --test ai` 20 件通過（loopback mock への 2 ターン履歴到達を含む）。
- `npm run test:unit` 31 ファイル 202 件通過（会話・inline target・Agent 送受信/取消/再試行・新規分離・stale 基準保持・Ctrl+I 起動と提案レビューを含む）。
- `npm run typecheck` 通過、`npm run ai-contracts:check` 通過。
- 未検証: 各 OS 実 WebView / IME での最終 QA は root が実施する。
