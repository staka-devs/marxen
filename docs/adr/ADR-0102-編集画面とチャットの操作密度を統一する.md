# 編集画面とチャットの操作密度を統一する

状態: 採用。日付: 2026-10-09。関連: #5、#12、#13、#17。

## 背景と選択肢

本文の編集を中心に、ファイル・設定・AI の操作を必要なときに使えるデスクトップ UI が必要である。Web フォーム風の大きなボタン、常設のラジオボタン、無効な承認操作、接続診断の常時表示は編集領域を圧迫する。

操作をすべて常設する構成と、コンパクトなヘッダー・入力欄・必要時に開く詳細へまとめる構成を比較した。

## 決定と理由

- アクティビティバー、フォルダーツリー、アイコン付きタブ、設定カテゴリに一貫した高さと選択状態を使う。ボタンは 28px、角丸は小さくする。
- ライブ表示は幅が広いときに本文を中央へ寄せ、行番号と本文を一緒に配置する。Markdown と分割の編集は利用可能な幅を使う。
- ステータスバーはファイル・Vim モード・位置・保存状態・接続状態を示す。revision と入力履歴は接続情報で確認する。カーソルの読み上げラベルを維持する。
- Agent とインラインに共通の入力欄の見た目を使う。モードを入力欄内の select で選び、履歴・新規会話・閉じる操作をヘッダーに置く。接続設定は折りたたむ。
- 適用済みのレビューは結果を折りたたみ、不要な承認ボタンを残さない。エラーと rollback は引き続き表示する。
- 設定はアプリ全体の中央に開き、Agent やサイドバーの幅に影響されない。

## 制約と確認方法

新しい UI ライブラリや状態管理基盤は追加しない。文書・AI の所有、revision 付き範囲編集、承認と Undo の契約を維持する。実 Windows WebView2 のライブ・左右分割・Agent・インライン・設定を目視確認し、本文不変、承認範囲、一回の UI Undo を Rust snapshot と照合する。ブラウザ回帰で狭い幅、テーマ、設定、描画とライブ操作を確認する。他 OS の実 GUI の結果は別に扱う。
