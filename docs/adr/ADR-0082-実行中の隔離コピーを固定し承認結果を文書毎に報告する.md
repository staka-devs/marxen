# ADR-0082-実行中の隔離コピーを固定し承認結果を文書毎に報告する

- 状態: 採用
- 日付: 2026-10-08
- 関連 Issue: #8、Epic #1
- 関連: ADR-0081 (選択範囲の隔離と提案取り込み)、ADR-0040 (保存競合と復旧)

## 背景

エージェント実行中の書き込みと承認・削除を競合させない。複数文書の適用が一部で失敗した場合も、各文書の結果とロールバックの成否を明示する必要がある。

## 検討した選択肢

1. 実行と承認を直列化しない / pin で固定する。コピー毎の pin 計数を持ち、ACP 子プロセスと HTTP stream の開始時に pin し、子 reap・stream 完了の settlement 時にのみ release する。取消要求だけでは release しない。pin 中の承認・却下・取消は拒否し、差分 (読み取りのみ) は許可するが実行完了後の取り直しを求める。
2. 承認失敗を単一 error で返す / 文書毎の結果で返す。承認前に全件 preflight (actor 生死・revision・disk・編集検証) を行い、適用は逐次で行って失敗時に native Undo で best-effort ロールバックする。結果は `ApproveResult` (文書毎の適用・revision・error・ロールバック有無と失敗) で返し、部分適用を明示する。失敗時はコピーを消費し、再同期は新規コピーで行う。
3. ロールバックを自動で完全に行う / best-effort と明示する。Undo 後の本文が承認前と一致した文書のみ rolled_back とし、不一致と Undo 失敗は rollback_error に残す。沈黙の all-or-nothing は作らない。

## 決定

- `ai_prompt_stream` は ACP と HTTP の両方で、生成・送信の副作用の前に解決・権威検証・pin を行い、settlement 後に release する。`ai_prompt_cancel` は pin を触らない。
- `isolation_approve` は `ApproveResult` を返す。preflight 失敗はコピーを残したまま error とし、適用-phase の失敗は `outcomes` とロールバック情報を返してコピーを消費 (Failed) する。保存は従来どおり共有保存契約が別途行う。
- 隔離はコピーであり OS サンドボックスではないことを UI 文言と文書に残す。

## 結果・制約

- 実行中の承認・削除競合は起こらない。承認結果は文書単位で表示・検証できる。失敗後の再実行は新規コピーが起点となり、古い差分の誤適用を防ぐ。
- pin 中の差分は実行完了後に取り直す運用とする。電源断・プロセス kill 時の保証は ADR-0040 の制約を引き継ぐ。

## 確認方法

- `cargo test --test isolation` の pin 中拒否と settlement 後承認、取消と settlement の分離、2 文書目の失敗とロールバック・明示結果、死んだ actor の preflight 拒否と native Undo・Redo の証跡。
- 各 OS の実 WebView / IME、認証済み CLI、配布後の資源配置は独立に検証し、結果は検証報告に記載する。
