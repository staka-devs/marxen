# ADR-0083-送信範囲の完全一致と実行完了後の端末配信を保証する

- 状態: 採用
- 日付: 2026-10-08
- 関連 Issue: #8、Epic #1
- 関連: ADR-0081 (選択範囲の隔離と提案取り込み)、ADR-0082 (実行固定と文書毎の報告)

## 背景

送信範囲と隔離コピーの範囲を完全に一致させる。準備に失敗した実行はコピーを固定せず、終了通知は子の終了と固定解除が済んでから配信する。承認前には実 Neovim の現在の本文と改訂を照合する。

## 検討した選択肢

1. 部分一致の送信を許す / 完全一致を求める。選択の変更は新規コピーを作れば足りるため、文書集合・revision・範囲の完全一致と抜粋照合を求め、narrowing・省略・追加・矛盾する重複を拒否する。
2. pin 取得後に準備失敗を許す / 準備を先にする。endpoint 解決と資格情報取得を pin より先に行い、欠落時は pin せずに失敗させる。権威検証は依然として通信より先である。
3. 端末を即時配信する / settlement 後に一度だけ配信する。`started` と `chunk` は即時、`done` / `cancelled` / `error` は子 reap・stream 完了と pin release の後に一度だけ配信する。沈黙の正常終了は内部 error で明示し、panic 経路も settlement する。
4. preflight を自前検証にする / 実 actor の `preflight_edits` を使う。入力待ち拒否・実ドリフト同期・revision と範囲の検証を `preflight_edits` に委ね、本文と Undo は不変とする。適用時の失敗は文書毎の結果と native Undo の best-effort ロールバックで報告し、ロールバック後の revision を記録してコピーを消費する。障害注入は検証用 manager の明示設定に限定する。

## 決定

- `authorize_prompt` は完全一致を要求する。`ai_prompt_stream` は HTTP でも資格情報準備→解決・権威検証・pin の順序を守る。
- 端末ゲート (`TerminalGate`) を ACP・HTTP 両経路に入れ、settlement と release の後に一度だけ配信する。完了順序は `docs/isolation.md` の連携節に固定する。
- `approve` の preflight は `preflight_edits` を全件 (変更なし文書を含む) に行う。

## 結果・制約

- 現在の送信範囲外の本文が ACP・HTTP のいずれにも渡らない。失敗した準備は pin を残さない。端末反応は settlement 後の安定 staging に対する。
- pin 中の差分は実行完了後に取り直す運用とする。電源断・プロセス kill 時の保証は ADR-0040 の制約を引き継ぐ。

## 確認方法

- `cargo test --test isolation` の scope 完全一致・資格情報欠落の非 pin・端末順序・隠れドリフトの preflight 拒否・注入失敗の部分結果とロールバック。
- `ai.rs` の端末ゲート unit と構造検証 unit。
- 各 OS の実 WebView / IME、認証済み CLI、配布後の資源配置は独立に検証し、結果は検証報告に記載する。
