# 描画依存の限定配布とビルド成果物の再利用

- 状態: 採用
- 日付: 2026-10-11
- 関連: #51

## 背景

Shiki の全言語・全テーマを含む入口は、アプリが使用しない定義も配布対象にする。MathJax を常時読み込む構成は、数式のない文書にも初期化の負担を課す。CI では型・描画・配布検証のために同じフロントエンドを繰り返しビルドしている。

## 決定

Shiki core に対応言語の定義、GitHub の明暗テーマ、Oniguruma を明示して渡す。ハイライターの共有、既存の言語 alias、未知の言語のテキスト表示を保持する。MathJax はサニタイズと数式検証を通過した数学ノードがある場合にローカルの非同期チャンクから読み込む。CDN は使用しない。

CI は同一 checkout の production build を一度作成し、その成果物をブラウザ E2E と Tauri 配布ビルドで使用する。E2E の再利用は明示した環境変数、Tauri の再利用は追加 config に限定する。通常の手動実行はビルドを省略しない。PR と main の変更を検証し、同じ PR の古い実行は取消す。検査項目は維持し、Rust・Node・テスト worker の並列数を制限する。

Rust の開発・テストではアプリの限定的なデバッグ情報を残し、外部 crate のデバッグ情報を省略する。debug assertion、overflow check、最適化レベル、リリースプロファイルは変更しない。

## 選択肢と制約

全 Shiki 定義の配布は対象外言語の出力を増やすため採用しない。数式機能の削除、CDN 化、テストの削減、チャンク警告の閾値変更による隠蔽も行わない。全テーマ・全言語の追加は別の製品要件として検討する。CI の再利用モードを手動で選ぶ場合は、同じソースから作成した dist が前提となる。

## 確認方法

全対応言語・alias、数式、サニタイズ、Mermaid、地図、3D の描画検証を実施する。dist のサイズとファイル数を比較し、再利用モードの E2E と native package を実行する。Cargo の正式プロファイルで test/check/Clippy/Rustdoc を実行する。各 OS の実 WebView・IME は CI の成功とは別に確認する。
