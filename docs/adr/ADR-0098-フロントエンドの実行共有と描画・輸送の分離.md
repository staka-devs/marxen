# ADR-0098: フロントエンドの実行共有と描画・輸送の分離

- 状態: 採用
- 日付: 2026-10-09
- 関連 Issue: #14

## 背景

Agent チャットとインラインチャットは別会話・別 mode・別履歴でありながら、実行 token・取消要求・確定 guard・停止 handle・busy 所有の手順が同一だった。Tauri 輸送の参照が component に残り、描画 helper が二重実装されていた。いずれも表示文言・配置・改訂管理・取消の効き方を変えずに整理する必要があった。

## 検討した選択肢

- 各 chat の lifecycle をそのまま残す: 取消・遅延確定の修正が二箇所に要り見送り。
- 実行全体を汎用 framework・port へ抽象化する: 未使用の抽象を増やすため見送り。
- 共有の実行 hook と純粋 helper に切り出し、輸送参照を `lib/` へ寄せ、描画 helper を単一化する: 採用。

## 決定

- Agent とインラインの token・取消・確定・停止・busy 所有・unmount cleanup を共有 hook とする。会話一覧・履歴・送信 mode・配置・Escape・差分確認導線の差分は各 component に残す。
- Claude Code の起動拒否と失敗の正規化、late-settle 時の handle 破棄を共有 helper とする。
- ネイティブの drag-drop 購読を `lib/` の関数とし、component から輸送の直接参照を除く。画像読込は workspace loader 経由に一本化し、bytes の dataURL 化を共有する。
- mdast の text 抽出と alert 判定、`escapeHtml` を単一化する。座標契約（CodeMirror 用 UTF-16 offsets／live-read 用 1-based lines）の入口は分離のまま。
- shell 内の同一 resolver 式と非 ask 取り込み連鎖を局所 helper に寄せる。共有 staging slot の所有（相互抑止・exact 一致時の再利用）は shell に残す。

## 結果・制約

- 実 Neovim 正本・revision 直列・stale 再同期・IME・Undo・early events の bounded queue・取消 fencing・質問 mode の表示専用・内部 ID 非表示を維持する。
- 画像の URL 判定と hydrate を UI に依存しない共通 module に置く。未使用の旧 renderer と全文書再構築型の置換は持たず、共通 renderer と revision 付き範囲編集を使用する。
- `WorkspaceShell` の責務集中とユースケースから具体的 Tauri adapter への依存は、残る制約として検証報告に記録する。
- 新規の port・framework・未使用抽象は追加しない。

## 確認方法

- 製品の振る舞い（送信・取消・遅延確定・unmount・会話切替・接続先変更・非表示保持・Vim 共存・範囲送信・差分適用）を UI テストで確認する。
- 実 WebView・IME の確認結果と未実施範囲の区別は検証報告に記載する。
